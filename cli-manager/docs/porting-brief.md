# 터미널 앱 Go + Wails 포팅 작업 지침

> 사용자 제공 원문. 라이선스 규칙(§1)은 모든 작업에 우선한다.

## 0. 작업 개요

BrightTerm **v1.1.0 태그(MIT License)** 의 코드를 기반으로, Electron 앱을 **Go 백엔드 + Wails 프런트엔드** 구조로 옮긴다. 그 다음, v1.1.0 이후 원본 프로젝트에 추가된 기능들을 아래 "기능 명세"만 보고 **Go와 Wails로 독자 구현**한다.

- 기준 소스: `https://github.com/Yeosup/BrightTerm` 의 `v1.1.0` 태그만 사용한다. (`git checkout v1.1.0`)
- 대상 플랫폼: Windows 우선. macOS·Linux는 동작을 깨지 않는 범위에서 선택 사항.

## 1. 라이선스 관련 필수 규칙 (반드시 지킬 것)

1. **v1.1.1 이후 태그·브랜치(main 포함)의 소스 코드를 열람, 참조, 복사, 번역하지 않는다.** v1.1.1부터는 MIT가 아닌 별도 라이선스(BrightTerm Source-Available License 1.0)가 적용된다.
2. v1.1.0 이후 기능은 이 문서의 **동작 설명만** 근거로 직접 설계·구현한다. 원본의 함수 구조, 파일 분할, 변수명을 재현하려 하지 않는다.
3. v1.1.0에서 가져온 코드(특히 재사용하는 React UI)는 MIT 저작권 고지를 유지한다. 앱의 정보 화면과 저장소 루트에 `Copyright (c) 2026 Dany Kim` MIT 고지를 포함한다.
4. 제품 이름과 로고는 BrightTerm 것을 쓰지 않는다. 새 이름·아이콘을 사용한다(임시 이름은 별도 지정 전까지 `TermGo` 등으로 둔다).
5. v1.1.0에 들어 있는 **광고 배너 기능은 이식하지 않는다**(배너 목록 다운로드, 배너 컴포넌트, 배너 이미지·캐시 일체 제거).

## 2. 아키텍처 방향

- 메인 프로세스(`src/main`)의 TypeScript/Node 코드는 Go로 다시 작성한다.
- 렌더러(`src/renderer`)의 React + xterm.js UI는 v1.1.0 것을 Wails 프런트엔드로 옮겨 재사용한다.
- 렌더러가 쓰던 preload 브리지(`window.bt`의 `call`/`on`/`write`/`resize`/`respond`/`pathForFile`/`platform`)는 동일한 인터페이스의 어댑터를 만들어 Wails 바인딩·이벤트로 연결한다. UI 코드는 가능한 한 손대지 않는다.
- Node 의존성 대체 후보:
  - SSH: `golang.org/x/crypto/ssh`
  - SFTP: `github.com/pkg/sftp`
  - 시리얼: `go.bug.st/serial`
  - 로컬 PTY(Windows ConPTY 포함): `github.com/aymanbagabas/go-pty` 또는 동급
  - 문자 인코딩(EUC-KR/CP949): `golang.org/x/text/encoding`
  - 볼트 암호화: `golang.org/x/crypto/scrypt` + 표준 `crypto/aes`, `crypto/cipher`(GCM)
  - OS 키 보관(Windows DPAPI 등): DPAPI 래퍼 또는 `github.com/zalando/go-keyring`
  - 텔넷: `net` 위에 IAC 협상 직접 구현
- 터미널 출력은 이벤트 수가 많으므로 Go 쪽에서 짧은 간격(약 10~16ms)으로 묶어서 프런트로 보낸다.
- 데이터 파일(서버 목록, 볼트, 설정)은 v1.1.0 형식과 호환되도록 유지하는 것을 기본으로 한다. 호환을 포기해야 할 경우 사용자에게 먼저 확인한다.

## 3. v1.1.0 이후 추가·변경된 기능 명세

아래는 원본 프로젝트의 공개 문서와 변경 이력에서 정리한 **사용자 관점의 동작**이다. 구현 방식은 자유롭게 정한다.

### 3.1 사이드바 ↔ 열린 창 연동

- 사이드바에서 서버를 클릭했을 때 그 서버의 세션이 이미 열려 있으면, 새로 열지 않고 해당 탭으로 이동해 그 패널에 포커스를 준다.
- 패널 하나가 확대(크게 보기) 상태라면 그 확대 상태 안에서 해당 패널로 이동한다.
- 같은 서버의 세션이 여러 개 열려 있으면 클릭할 때마다 다음 세션으로 순환한다.
- 사이드바 더블클릭은 열린 세션이 없을 때만 새로 연다. 연결이 끊긴 패널도 "열린 것"으로 취급한다.
- 같은 서버를 하나 더 열고 싶을 때는 사이드바 항목에 마우스를 올리면 나타나는 ▶ 버튼을 쓴다.
- 반대 방향 연동: 사용자가 패널 간에 포커스를 옮기면, 사이드바가 그 패널의 서버를 선택 상태로 바꾸고 보이도록 스크롤한다.

### 3.2 점프 호스트 직접 입력

- 기존에는 점프 호스트(베스천)로 쓸 서버를 먼저 별도 서버로 등록해야 했다. 이제 서버 편집 → 고급 → 점프 호스트 목록에 **"직접 입력"** 항목을 추가한다.
- "직접 입력"을 고르면 그 서버 설정 안에서 베스천의 주소, 포트, 사용자, 인증 방식(비밀번호/키), 자격 증명을 바로 입력한다.
- 주소 입력란에 `user@host:port` 형식으로 넣으면 사용자·호스트·포트로 자동 분리해 채운다.
- 베스천의 키·비밀번호는 볼트에 암호화해 저장하며, 볼트 안에서 "<서버 별칭> 베스천" 같은 이름으로 구분되게 한다.
- 접속 시에는 기존 다단계 점프 경로와 동일하게 베스천을 거쳐 대상 서버에 한 번에 접속하고, 대상 서버에 설정된 포트 포워딩도 함께 연다.
- 버그 방지 요구사항: 베스천 단계에서 비밀번호를 묻는 창에 "저장"을 체크해도, 그 비밀번호가 **대상 서버의 계정 정보를 덮어쓰면 안 된다.** 베스천 자격 증명과 대상 서버 자격 증명은 분리해 저장한다.

### 3.3 세션 유지 (tmux)

- 서버(SSH)와 로컬 터미널의 편집 화면 → 고급 탭에 **"세션 유지"** 스위치를 추가한다.
- 켜져 있으면 접속(또는 로컬 셸 시작) 직후 지정한 이름의 tmux 세션에 붙는다. 세션이 없으면 새로 만든다.
  - 새로 만들 때 tmux의 마우스 모드를 켜고 상태 표시줄을 끈다(휠 스크롤이 자연스럽게 되도록).
  - "자동 실행 명령"은 tmux 세션을 **처음 만들 때만** 그 세션 안에서 실행한다. 이미 있는 세션에 다시 붙을 때는 실행하지 않는다.
- 효과: 앱 창이나 앱 자체를 닫아도 tmux 안의 프로그램은 계속 실행되고, 다시 열면 그 화면에 그대로 붙는다. 연결이 끊긴 뒤 자동 재접속 시에도 다시 붙는다.
- tmux 세션 이름 입력란(고급 탭)을 둔다. 비워 두면 서버 별칭이나 로컬 폴더 이름으로 자동 생성한다.
- 대상에 tmux가 없으면 사용자에게 안내를 보여 주고 평소처럼(tmux 없이) 접속한다.
- 플랫폼: 원격 서버, macOS 로컬, Windows 로컬은 **WSL 셸일 때만** 지원.
- UI 표시:
  - 세션 유지 중인 패널 머리글에 "유지" 배지를 표시한다.
  - 창/탭을 닫을 때 확인 창에 "안의 프로그램은 계속 실행된다, 완전히 끝내려면 그 창에서 `exit`" 취지의 안내를 넣는다.
- tmux 안에서도 글자 선택이 되도록 수정키+드래그 선택을 지원한다(Windows: Shift+드래그, macOS: ⌥+드래그).
- 새로 만드는 로컬 터미널은 시스템에 tmux가 있으면 세션 유지를 **기본으로 켠다.** tmux 탐지는 PATH 외에 일반적인 설치 위치도 확인한다. 단, 단축키로 즉석에서 여는 로컬 창은 예외(세션 유지 안 함).
- 자동 실행 명령 입력란에 예시 placeholder를 보여 준다(로컬 예: `claude --continue`, SSH 예: `cd /var/www && sudo -i`). 세션 유지가 켜져 있으면 "세션을 처음 만들 때만 실행됨" 안내를 함께 보여 준다.

### 3.4 탭·분할 레이아웃 복원

- 앱을 닫을 때 열려 있던 탭과 분할 배치를 저장하고, 다음 실행 시 그대로 다시 열어 접속한다.
- 저장하는 정보는 배치 구조와 각 칸의 서버 식별자(또는 로컬 폴더)뿐이다. 비밀번호·화면 내용은 저장하지 않는다.
- 복원은 볼트 잠금이 해제된 뒤 한 번 수행한다.
- 저장되지 않은 즉석 SSH 접속(빠른 접속으로 바로 연 창 등)은 비밀번호가 필요하므로 복원 대상에서 제외한다.
- 세션 유지를 켠 창은 복원 시 기존 tmux 세션에 붙어 하던 화면으로 돌아온다.
- 설정 → 연결에서 이 기능을 끌 수 있다.

### 3.5 창 크기·위치 기억

- 앱 창의 크기, 위치, 최대화 상태를 저장하고 다음 실행 시 그대로 연다.
- 모니터 구성이 바뀌어 저장된 위치가 화면 밖이면 주 화면 가운데로 연다.
- 설정 → 모양에서 이 기능을 끄거나 **"원래 크기로"** 버튼으로 기본 크기·위치로 되돌릴 수 있다.

### 3.6 새 버전 알림

- 앱 시작 시와 이후 12시간마다 배포 저장소의 최신 릴리스를 확인한다(포팅본은 자기 저장소 기준으로 설정).
- 새 버전이 있으면 상태 표시줄에 알림을 표시하고, 처음 발견했을 때 한 번 안내한다.
- 이 요청에는 서버 목록, IP, 계정 등 어떤 사용자 정보도 담지 않는다.
- 설정 → 정보에서 자동 확인을 끄거나 "지금 확인"을 누를 수 있다.
- 폐쇄망 환경을 고려해 확인 실패는 조용히 무시한다.

### 3.7 SSH 접속 오류 처리 안정화

- 접속 과정에서 오류가 연속으로 여러 번 발생해도(예: 첫 오류 후 "핸드셰이크 전에 연결이 끊김" 같은 두 번째 오류) 앱 전체가 예외로 멈추거나 오류 대화상자를 띄우면 안 된다. 모든 오류는 해당 패널의 "연결 실패/끊김" 상태로만 처리한다.

### 3.8 분할 칸 관리: 빈 칸, 칸 옮기기, 끌어 놓기

- 분할 상태에서 한 칸의 세션을 닫으면 그 자리가 **빈 칸**으로 남는다(레이아웃이 즉시 무너지지 않음). 빈 칸을 다시 닫으면 그 칸이 레이아웃에서 제거된다.
- 빈 칸에 세션 열기:
  - 사이드바의 서버를 빈 칸으로 끌어다 놓으면 그 자리에서 연다.
  - 빈 칸을 선택한 상태에서 사이드바 서버를 더블클릭하면 그 자리에서 연다.
- 칸 머리글 드래그:
  - 다른 칸의 **가운데**에 놓으면 두 칸의 자리를 맞바꾼다.
  - 다른 칸의 **가장자리**(상하좌우)에 놓으면 그 방향으로 칸을 옮긴다.
- 사이드바 서버를 기존 칸의 가장자리에 끌어 놓으면 그 방향으로 분할해 새로 연다.
- 사이드바 서버 우클릭 → **"위치 골라서 연결…"**: 열린 탭마다 현재 배치를 축소 그림으로 보여 주고, 각 칸의 방향 화살표(그 방향으로 분할)나 빈 칸을 눌러 열 위치를 고른다.
- 빈 칸 상태도 3.4의 레이아웃 복원 대상에 포함한다.

### 3.9 Shift+Enter 줄바꿈

- 터미널에서 Shift+Enter를 누르면 명령을 실행하지 않고 줄만 바꾸는 신호(ESC + CR, Alt+Enter와 동일한 시퀀스)를 보낸다. Claude Code 같은 CLI의 여러 줄 입력용.
- 설정 → 입력에서 끌 수 있다.

### 3.10 OSC 52 원격 복사

- 원격 프로그램(tmux 마우스 선택, vim, Claude Code 등)이 OSC 52 시퀀스로 보내는 "클립보드에 쓰기" 요청을 받아 로컬 PC 클립보드에 넣는다.
- 원격이 로컬 클립보드를 **읽으려는** OSC 52 요청은 보안상 거절한다.
- 설정 → 입력에서 끌 수 있다.

### 3.11 접속 정보·볼트 git 동기화

- 설정 → 동기화(git)에 비공개 git 저장소 주소를 입력하면 서버 목록, 폴더, 스니펫, 저장된 계정을 여러 PC 간에 맞춘다.
- 저장소에는 **볼트 키로 암호화된 동기화 파일 하나**만 올린다. 서버 주소·계정명을 포함해 어떤 정보도 평문으로 남기지 않는다.
- 다른 PC는 같은 마스터 비밀번호로 그 파일을 연다.
- 병합 규칙: 마지막 동기화 시점을 기준으로 한 3방향 병합.
  - 한쪽에서 삭제한 항목은 다른 PC에서도 삭제된다.
  - 양쪽에서 같은 항목을 수정했으면 지금 동기화하는 PC 쪽 내용이 남는다.
- 저장소의 볼트가 이 PC의 볼트와 다른 볼트이면(처음 연결 등) "저장소 볼트 받기" 또는 "이 PC 볼트로 덮어쓰기" 중 사용자가 고르게 한다. 새 PC에서는 "받기"를 안내한다.
- 자동 동기화 시점: 볼트를 열 때, 데이터 변경 후 약 20초 뒤, 그리고 10분마다.
- 인증은 그 PC에 설치된 git과 그 설정(SSH 키, 자격 증명 도우미)을 그대로 사용한다. 앱이 git 자격 증명을 따로 저장하지 않는다.

### 3.12 리눅스 OS 키링으로 볼트 잠금 해제 (선택)

- Linux에서 GNOME 키링 또는 KDE 지갑(KWallet)으로 볼트를 잠금 해제할 수 있게 한다.
- 사용 가능한 백엔드를 자동으로 고르되, 설정에서 특정 백엔드로 고정할 수 있다.
- 안전한 저장소가 없어 평문에 가까운 기본 저장만 가능한 환경이면 이 기능을 끈다.
- Windows 우선 대상이므로 우선순위는 낮다.

### 3.13 광고 배너 관련 (구현하지 않음)

원본은 v1.2.x에서 광고 배너 자동 전환 등을 추가했다가 1.3.0에서 완전히 제거했다. 포팅본에는 광고 관련 기능을 **처음부터 넣지 않는다.** v1.1.0에 남아 있는 배너 코드·이미지·캐시도 모두 제거한다.

## 4. 권장 작업 순서

1. v1.1.0 체크아웃 → Wails 프로젝트 생성 → React UI 이식, `window.bt` 호환 어댑터 작성.
