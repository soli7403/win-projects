# ZMODEM 파일 전송 (sz · rz)

> 작성 방식: 새 기능의 동작 정의(기존 앱에 없던 기능이라 관찰 대상이 없다). 통신 형식은 공개 규격(Chuck Forsberg, "The ZMODEM Inter Application File Transfer Protocol")을 따른다. 작성일 2026-11-23, 결정 D114. 상태: **ready**.

## 1. 무엇을 하는가

터미널에서 서버의 `sz 파일` 을 실행하면 그 파일을 이 PC 로 받고, `rz` 를 실행하면 이 PC 에서 고른 파일을 서버로 보낸다. SFTP 를 쓸 수 없는 곳(경유 서버를 여러 번 거쳐 들어간 셸, `sudo`·`su` 로 바꾼 계정, 시리얼로 붙은 장비)에서 쓰는 방법이다. 서버에 `lrzsz` 같은 ZMODEM 프로그램이 있어야 한다.

## 2. 적용 범위

- **SSH 와 시리얼 세션**에서만 동작한다.
- **로컬 터미널**은 하지 않는다(가상 터미널이 이진 데이터를 바꾼다). **텔넷**도 하지 않는다(이진 전송 방식을 협상하지 않아 데이터가 바뀔 수 있다).
- 설정 `zmodemEnabled`(기본 켜짐)가 꺼져 있으면 아무 일도 하지 않고, 서버가 보낸 시작 표시가 그대로 화면에 나온다.
- tmux 안에서는 tmux 가 이진 데이터를 다시 그리므로 대개 동작하지 않는다(알려진 한계).

## 3. 시작

- 세션 출력에 **시작 표시**가 나타나면 전송을 시작한다. 시작 표시는 16진 헤더의 앞부분 `* * 0x18 B 0` 다음에 `0`(서버가 보내려 함, `sz`) 또는 `1`(서버가 받으려 함, `rz`)이 오는 것이다. 표시가 출력 묶음 경계에 걸쳐 와도 찾는다.
- 표시 **앞의 출력은 그대로 화면에 보낸다**(`sz` 가 먼저 찍는 `rz` 글자 등).
- 표시처럼 보였지만 뒤가 올바른 헤더가 아니면(검사값 불일치) 전송하지 않고 읽은 바이트를 화면 출력으로 되돌린다.
- **tmux·screen 안에서는 전송할 수 없다**(한계, 2026-11-25 D125): 다중화기가 안에서 돈 프로그램의 출력을 해석해 다시 그리면서 제어 문자 0x18 을 버리므로 시작 표시도 전송 데이터도 깨져서 온다. 0x18 이 빠진 시작 표시(`**B0` + `0` 또는 `1` + 16진 소문자 12자 — 예: `**B00000000000000`, `**B0100000023be50`)가 출력에 나타나면 전송은 시작하지 않고, 그 출력은 그대로 화면에 낸 뒤 안내 한 줄을 낸다: `ZMODEM 시작 표시가 깨져서 왔습니다 — tmux·screen 안에서는 전송할 수 없습니다. Ctrl+X 를 5번 눌러 끝내고 tmux 밖에서 다시 실행하세요`. 같은 안내는 **10초 안에 다시 내지 않는다**. 서버로는 아무것도 보내지 않는다(그 글이 실행 중인 `sz`·`rz` 의 것이 아닐 수 있다). `zmodemEnabled` 가 꺼져 있으면 살피지 않는다. (서버의 `sz`·`rz` 는 터미널을 날것 방식으로 바꿔 두어 Ctrl+C 로는 끝나지 않고, Ctrl+X 5번이 중단 신호다.)
- 전송이 시작되면 끝날 때까지 **그 연결의 입출력을 전송에만 쓴다**: 서버가 보낸 바이트는 화면에 나오지 않고, **터미널 입력은 서버로 보내지 않는다**(전송 데이터에 섞이지 않게). 일괄 입력으로 들어온 입력도 같다.

## 4. 받기 (서버에서 `sz`)

- 저장 폴더: 설정 `zmodemDownloadDir`. 비면 OS 의 다운로드 폴더(`~/Downloads`). `~` 로 시작하면 홈으로 바꾼다. 폴더가 없으면 만든다.
- **파일 이름**은 서버가 준 이름을 다듬어 쓴다: 경로는 떼고 파일 이름만(폴더 밖에 쓰지 못하게), `\ / : * ? " < > |` 와 제어 문자는 `_`, 끝의 공백·점 제거, 200자까지, 비면 `zmodem-file`, Windows 장치 이름(`CON`, `NUL`, `COM1` 등)은 앞에 `_`.
- **같은 이름이 있으면 덮어쓰지 않는다**: `이름 (2).확장자`, `이름 (3).확장자` … 로 저장한다.
- 받는 동안은 `<이름>.dtpart` 에 쓰고, **다 받은 뒤에만** 최종 이름으로 바꾼다. 취소·실패·끊김이면 `.dtpart` 파일을 지운다(끊겨서 지우지 못하면 남는다).
- 서버가 수정 시각을 알려 주면 받은 파일의 수정 시각을 그 값으로 맞춘다.
- 여러 파일(`sz a b c`)을 차례로 받는다.

## 5. 보내기 (서버에서 `rz`)

- 파일 선택 대화상자(제목 "ZMODEM으로 보낼 파일 선택", 여러 개 선택 가능)를 띄운다. 그 전에 터미널에 안내 "ZMODEM 보내기: 보낼 파일을 고르세요 (취소하면 전송을 그만둡니다)".
- 고르지 않고 닫으면 전송을 취소하고 서버의 `rz` 를 끝낸다.
- 폴더와 읽을 수 없는 항목은 빼고 보낸다. 서버에는 경로 없이 **파일 이름만** 알린다.
- 서버가 같은 이름을 이미 갖고 있어 건너뛰라고 하면 그 파일은 건너뛴다.
- 파일 선택 대화상자가 없는 OS(Windows 가 아닌 곳)에서는 보내기를 할 수 없다(취소로 끝난다). 받기는 된다.

## 6. 진행 표시와 안내 (터미널 안, 청록색 `●`)

| 때 | 문구 |
|---|---|
| 전송 중(0.25초에 한 번 같은 줄을 고쳐 씀) | `ZMODEM 받는 중: {이름} {백분율}% ({받은 크기} / {전체 크기}) · Ctrl+C 취소` / `ZMODEM 보내는 중: …` |
| 파일 하나를 다 받음 | `받음: {이름} ({크기}) → {저장된 경로}` |
| 파일 하나를 다 보냄 | `보냄: {이름} ({크기})` |
| 건너뜀 | `건너뜀: {이름}` |
| 모두 끝남 | `ZMODEM 전송 완료: 파일 {n}개, {크기}` |
| 사용자가 취소 | `ZMODEM 전송을 취소했습니다` |
| 서버가 중단 | `서버 쪽에서 ZMODEM 전송을 중단했습니다` |
| 그 밖의 실패 | `ZMODEM 전송 실패: {오류}` |

- 전체 크기를 모르면 백분율 없이 받은 크기만 보인다.
- 크기 단위는 B · KB · MB · GB(1024 단위).
- **전송 중인 줄은 세션 로그에 남기지 않는다.** 나머지 안내 줄은 로그에도 남는다.
- 파일 이름의 제어 문자는 `_` 로 바꿔 보인다.

## 7. 취소

- 전송 중에 터미널에서 **Ctrl+C** 를 누르면 취소한다: 서버에 중단 신호(CAN 8개)를 보내고, 받던 파일은 지운다.
- 취소한 뒤 도착한 전송 데이터는 화면에 내보내지 않고 버린다. 그 뒤의 출력(셸 프롬프트)부터 다시 화면에 나온다.
  - (2026-11-25, D123-2) 받는 중에 취소·실패하면 서버가 이미 보낸 데이터가 한동안 더 온다. **0.5초 동안 아무것도 오지 않을 때까지** 읽어 버리고(최대 20초 — 넘으면 버리기를 그만둔다), 마지막 데이터 조각 바로 뒤에 붙어 온 256바이트 이하의 출력(셸 프롬프트)만 화면에 낸다. 그동안의 입력은 서버로 보내지 않는다. 취소 안내 줄은 이 뒤처리가 끝난 뒤에 나온다.
- 세션을 닫거나 연결이 끊기면 전송도 끝난다(끊김 처리는 보통 세션과 같다 — 자동 재접속 규칙 적용).
- **응답 시한 60초** (2026-11-25, D125 — 전에는 시간 제한이 없었다): 앱이 서버의 응답을 기다리는 동안 **60초** 동안 한 바이트도 오지 않으면 서버에 중단 신호를 보내고 전송을 끝낸다. 연결은 끊지 않는다(세션은 그대로 쓴다). 안내: `서버가 60초 동안 응답하지 않아 ZMODEM 전송을 중단했습니다`. 받던 파일은 지운다. 보낼 파일을 고르는 동안(파일 선택 창)은 시한에 넣지 않는다.
- **Ctrl+C 는 서버가 조용해도 곧바로 듣는다**(0.1초 안, D125): 전에는 취소한 뒤 서버에서 다음 바이트가 와야 전송 상태가 풀렸다.

## 8. 오류 복구와 한도

- 받은 데이터의 검사값이 맞지 않으면 그 위치부터 다시 보내 달라고 요청해 이어 받는다. 전송 하나에서 이런 오류가 **10번**을 넘으면 실패로 끝낸다.
- 보낼 때는 데이터를 **1024바이트 조각**으로 보내고 **256조각(약 256KB)마다** 서버의 확인을 기다린다. 서버가 다른 위치부터 다시 달라고 하면 그 위치부터 다시 보낸다.
- 서버가 CRC-32 를 쓸 수 있다고 알리면 CRC-32 로, 아니면 CRC-16 으로 보낸다. 받을 때는 둘 다 받는다.
- 보낼 때 제어 문자(0x00~0x1f, 0x7f, 0x80~0x9f, 0xff)는 모두 바꿔서(이스케이프) 보낸다.
- 4GB 를 넘는 파일은 보장하지 않는다(규격의 위치 값이 32비트다).
- 이어받기(끊긴 전송을 중간부터 다시)는 하지 않는다: 항상 처음부터 받는다.

## 9. 설정

| 설정 | 기본값 | 내용 |
|---|---|---|
| `zmodemEnabled` | true | ZMODEM 을 쓸지. 바꾸면 열려 있는 세션에도 곧바로 적용된다(다음 시작 표시부터) |
| `zmodemDownloadDir` | 빈 값 | 받은 파일 폴더. 비면 OS 의 다운로드 폴더 |

화면은 ui/settings.md §3.

## 10. 수용 시나리오

| # | 조건 | 동작 | 기대 결과 |
|---|---|---|---|
| Z1 | SSH 세션, 서버에 lrzsz | `sz /etc/hostname` | 진행 줄이 보인 뒤 `받음: hostname (…) → …\Downloads\hostname`, `ZMODEM 전송 완료: 파일 1개, …`. 파일 내용이 서버와 같다. 셸 프롬프트가 다시 나온다 |
| Z2 | Z1 을 한 번 더 | `sz /etc/hostname` | `hostname (2)` 로 저장된다. 처음 파일은 그대로다 |
| Z3 | SSH 세션 | `rz` → 대화상자에서 파일 2개 선택 | 두 파일이 서버의 현재 폴더에 생기고 내용이 같다 |
| Z4 | `rz` 실행 | 대화상자를 취소 | `ZMODEM 전송을 취소했습니다`. 서버의 `rz` 가 끝나고 프롬프트가 나온다 |
| Z5 | 큰 파일을 `sz` 로 받는 중 | Ctrl+C | 전송이 멈추고 `.dtpart` 파일이 지워진다. 그 뒤 입력이 정상으로 간다 |
| Z6 | 큰 파일을 받는 중 | 글자를 친다 | 서버로 가지 않는다(전송이 깨지지 않는다) |
| Z7 | 설정에서 ZMODEM 을 끔 | `sz 파일` | 전송하지 않고 서버가 보낸 글자가 화면에 그대로 나온다 |
| Z8 | 서버가 `../../x` 같은 이름을 알림 | 받기 | 받는 폴더 안에 `x` 로 저장된다(폴더 밖에 쓰지 않는다) |
| Z9 | 큰 파일(수십 MB)을 `sz` 로 받는 중 | Ctrl+C | `ZMODEM 전송을 취소했습니다` 뒤에 프롬프트가 나온다. 화면에 깨진 글자(전송 데이터)가 나오지 않는다 (D123-2) |
| Z10 | 서버에서 `printf '**\030B00000000000000\r\212\021'; sleep 300` (시작만 하고 멈춘 서버 흉내) | 60초 기다림 | `서버가 60초 동안 응답하지 않아 ZMODEM 전송을 중단했습니다`. 세션은 연결된 채이고 입력이 다시 서버로 간다 (D125) |
| Z11 | Z10 과 같은 명령 | 곧바로 Ctrl+C | 1초 안에 `ZMODEM 전송을 취소했습니다`. 입력이 다시 서버로 간다 (D125) |
| Z12 | tmux 안에서 `sz /etc/hostname` | — | 전송은 시작되지 않고 `**B00000000000000` 같은 글 뒤에 "tmux·screen 안에서는 전송할 수 없습니다…" 안내가 한 번 나온다. Ctrl+X 를 5번 누르면 `sz` 가 끝난다 (D125) |
