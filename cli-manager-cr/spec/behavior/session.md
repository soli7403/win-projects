# 세션 수명주기 — 접속·재접속·종료·세션 유지(tmux)

> 작성 방식: 기존 앱 동작 열람. 작성일 2026-11-10. 상태: **draft**. 프로토콜별 접속 방식은 protocols.md.

## 1. 세션 정보 (화면에 쓰이는 값)

| 필드 | 값 |
|---|---|
| id | UUID v4 |
| hostId | 저장된 서버면 서버 id, 즉석 접속이면 없음(null) |
| title | 서버 별칭. 즉석 SSH/텔넷은 `[사용자@]호스트`, 즉석 로컬은 "로컬 터미널" |
| protocol | ssh / telnet / serial / local |
| target | 접속 대상 문자열(아래) |
| color | 저장된 서버만: 서버 색 → 환경색 → 폴더(상위 최대 32단계) 색/환경색. 없으면 없음 |
| env | 저장된 서버만: 서버 환경(`none` 제외) → 폴더(상위 최대 32단계)의 환경 → `none`. 즉석 연결은 `none` |
| state | connecting / connected / reconnecting / closed / error |
| connectedAt | 연결된 시각(ms) |
| message | 재접속 대기 시 안내 등 |
| canSftp | protocol 이 ssh 이면 true |
| keepSession | 세션 유지가 적용되는 서버면 true |

**target 문자열**: SSH/텔넷 `[사용자@]호스트:포트`, 시리얼 `{장치} @ {속도}`(없으면 `? @ 9600`), 로컬 `로컬 · {시작 폴더, 비면 ~}`.

즉석 접속 기본값: 인증 `ask`, 인코딩 utf-8, 터미널 종류 xterm-256color, keepalive 30초, 포트 비면 SSH 22 / 텔넷 23. 로컬은 시작 폴더만.

## 2. 상태 전이

```
(열기) → connecting ─성공→ connected ─끊김→ [재연결 규칙] → reconnecting → connecting …
            │                                   └─ 규칙 불충족 → closed(끊김) 또는 error(접속 실패)
            └─실패→ [재연결 규칙]
```
- **열기 직후** `connecting`, 연결 시도가 **재시도**이면 `reconnecting`.
- 접속이 성공하면 `connected`(시각 기록), 재시도 횟수는 0 으로 되돌린다.
- 상태가 바뀔 때마다 상태 이벤트를 보낸다.

## 3. 터미널에 나오는 안내 줄

세션은 터미널 화면 안에 `● 메시지` 형식의 한 줄(색 있는 글씨)을 직접 출력한다. 색: 정보=회색, 경고=노랑, 오류=빨강.
- 접속 시작(로컬 제외): `● {제목} ({대상}) 연결 중...`(회색). 연결되면 그 줄을 지운다(줄 지우기 + 커서 처음).
- 접속 실패: `● 연결 실패: {오류}`(빨강). 로컬은 `● 셸 실행 실패: {오류}`.
- 로컬 시작 폴더 보정: `● 시작 폴더({지정값})가 없어 홈 폴더에서 엽니다`(노랑).
- 연결 끊김: `● 연결 끊김: {이유}`(노랑) 또는 이유가 없으면 `● 연결이 끊어졌습니다`.
- 로컬 셸 종료: `● {이유 또는 "셸이 종료되었습니다"} — Enter 키를 누르면 새 셸을 엽니다.`(회색)
- 자동 재접속 예약: `● {n}초 후 자동 재연결합니다... (Enter: 즉시 재연결)`(회색)
- 재접속 포기: `● Enter 키를 누르면 다시 연결합니다.`(회색)
- 서버가 세션을 정상 종료(§4): `● 서버가 세션을 끝냈습니다.`(회색) 다음 줄에 `● Enter 키를 누르면 다시 연결합니다.`(회색). (2026-11-17)
- 앱 잠금 해제 대기(§4): `● 앱 잠금을 해제하면 다시 연결합니다.`(회색). 대기에 들어올 때 한 번만. (2026-11-17)
- 점프/포워딩/키/비밀번호 저장 안내는 protocols.md.

**오류 문구 번역**(접속 실패 이유가 아래 단어를 포함하면 해당 문구로 바꿔 보여 준다, 대소문자 무시, 위에서 아래 순서로 첫 일치):
| 포함 단어 | 보여 줄 문구 |
|---|---|
| refused / actively refused | 서버가 접속을 거부했습니다 (포트 확인) |
| timed out / i/o timeout | 응답 시간 초과 (주소·방화벽 확인) |
| no such host | 호스트 이름을 찾을 수 없습니다 |
| unreachable | 네트워크에 도달할 수 없습니다 |
| unable to authenticate / no supported methods | 인증 실패 (사용자 이름/비밀번호/키 확인) |
| host key rejected | 호스트 키를 승인하지 않아 접속을 중단했습니다 |
| access is denied / cannot find the file | `{원문} (포트 사용 중이거나 권한 없음)` |
| (그 외) | 원문 |

## 4. 재접속 규칙

- **자동 재접속 조건**: 설정 "연결이 끊기면 다시 연결"이 켜져 있고 **시리얼이 아니며**, (연결이 끊긴 경우이거나 접속 **실패가 이미 한 번 이상 재시도된 후**) 그리고 재시도 횟수 < 8.
  - 즉 **처음 접속이 실패하면 자동 재접속하지 않는다**(곧바로 오류). 한 번 연결됐다가 끊기면 자동 재접속을 시작하고, 재접속 시도가 실패하면 계속 시도한다.
- 대기 시간: `min(30, 2 × 2^(시도 횟수))` 초 → 2, 4, 8, 16, 30초(최대 5회, D62). 예약할 때 상태를 `reconnecting`, 메시지 `{n}초 후 재접속 ({시도}/8)` 로 하고 §3 안내 줄을 출력.
- 규칙을 충족하지 않으면(자동 재접속 꺼짐·시리얼·5회 초과 등) 시도 횟수를 0 으로 되돌리고, **접속 실패였으면 상태 `error`, 끊김이었으면 `closed`** 로 하고 "Enter 키를 누르면 다시 연결합니다." 를 출력.
- **수동 재접속**: 사용자가 칸의 [재연결] 버튼·메뉴를 쓰거나, **끊긴(연결 없는) 세션에서 Enter(CR) 입력**을 하면(접속 중이 아닐 때) 즉시 재접속한다. 대기 중인 예약 타이머는 취소. 이미 연결되어 있으면 아무 일 없음. **로컬 셸이 종료된 뒤 Enter 를 누르면 새 셸을 연다**(같은 규칙).
- **서버가 정상 종료한 세션은 자동 재접속하지 않는다**(2026-11-17): SSH 셸이 **종료 코드(0 포함) 또는 신호와 함께** 끝났으면(서버의 유휴 자동 로그아웃, 사용자의 `exit`·`logout`, 관리자의 세션 종료) "끊김"이 아니라 정상 종료로 본다. 상태 `closed`, 시도 횟수 0, §3 의 정상 종료 안내 두 줄을 출력하고 남은 SSH 연결(포워딩·keepalive 포함)을 닫는다. Enter·[재연결] 로 다시 연결하는 것은 그대로. 종료 코드 없이 채널이 닫혔거나 전송 오류로 끝나면(네트워크 단절, keepalive 실패, 절전 복귀) 지금처럼 끊김이다. 세션 유지(tmux)를 켠 서버도 같은 규칙. 텔넷은 둘을 구분할 수 없어 끊김으로 둔다. (서버의 유휴 로그아웃을 피하려는 가짜 입력은 보내지 않는다 — 서버 보안 정책을 우회하는 동작.)
- **앱 잠금 해제 대기**(2026-11-17, protocols.md §2.2): SSH 접속(처음 열기·자동·수동 재접속 모두)에 볼트가 필요한데 볼트가 잠겨 있으면 — 저장된 계정을 읽을 수 없고 세션 사본도 없거나, 사본으로 안 되어 질문 창이 필요하면 — 접속을 멈추고 상태 `reconnecting`, 메시지 `앱 잠금을 해제하면 다시 연결합니다.`, §3 안내 줄을 출력한다. **실패로 세지 않는다**(시도 횟수 불변, 오류 상태로 가지 않음, 예약 타이머 없음). 볼트가 열리면 기다리던 세션을 **곧바로** 다시 접속한다(닫힌 세션·이미 접속 중인 세션은 제외). 기다리는 중 Enter·[재연결]은 다시 시도하며, 아직 잠겨 있으면 같은 대기로 돌아간다(안내 줄은 다시 내지 않는다). 볼트를 만들지 않은 사용자는 이 규칙이 없다(지금처럼 묻는다).
- **접속이 겹치지 않음**: 한 세션의 접속 시도는 한 번에 하나다. 접속 중에 온 Enter·[재연결]·잠금 해제 재개는 무시한다.
- **오래된 연결의 콜백 무시**: 재접속할 때마다 연결 "세대"를 올려, 이전 연결에서 늦게 오는 출력·종료 알림은 무시한다.
- 접속 중 발생한 어떤 오류·패닉도 해당 칸의 "연결 실패" 처리로만 끝나며 앱 전체에는 영향이 없다.

## 5. 접속 직후 처리

1. 저장된 서버면 서버의 `lastUsedAt` 갱신.
2. 설정 "터미널 출력 기록"이 켜져 있으면 로그 파일을 연다(§6).
3. **세션 유지(tmux)가 적용되면**(§7) 500ms 뒤 tmux 접속 명령을 셸에 입력한다. 아니면 서버의 **자동 실행 명령**이 있으면 줄바꿈을 CR 로 바꾸고 끝에 CR 을 붙여 400ms 뒤에 입력한다.

## 6. 세션 로그
- 설정 "터미널 출력 기록"(`sessionLog`)이 켜져 있을 때 **세션을 열 때 한 번** 로그 폴더(`<데이터 폴더>\logs`)에 `{표시 이름}-{YYYYMMDD-HHmmss}.log` 를 **새로 만든다**(권한 소유자 전용). 같은 이름이 이미 있으면 `.log` 앞에 `-2`, `-3`, … 을 붙여 없는 이름으로 만든다(세션 하나에 파일 하나). 1000번까지 시도해도 못 만들면 로그 없이 연다.
- 파일 이름의 표시 이름: 별칭의 `\ / : * ? " < > |` 와 제어 문자는 `_` 로 바꾸고, 앞뒤 공백·점을 지우며, 80자로 자른다. 비면 `session`.
- 기록 내용: 화면 출력에서 **ANSI 이스케이프 시퀀스를 제거**하고 CR 도 제거한 텍스트. 시퀀스가 출력 묶음 경계에서 잘려도 이어 붙여 지운다(종결 없이 256바이트를 넘는 ESC 는 시퀀스로 보지 않고 그대로 둔다). 디스크에는 **약 1초 단위로 모아서** 쓰고, 세션을 닫을 때 남은 것을 쓴다(앱이 비정상 종료하면 마지막 1초 분량이 빠질 수 있다).
- 자동·수동 재접속은 같은 파일에 이어 쓰고, 세션을 닫으면 파일을 닫는다. 설정을 바꾸면 **새 세션부터** 적용.
- **보관 기간**: 설정 `sessionLogKeepDays`(기본 30, 0 이면 지우지 않음). 앱은 시작 약 10초 뒤와 그 뒤 **1시간마다** 로그 폴더 바로 아래의 `.log` 파일 중 수정 시각이 그 일수보다 오래된 것을 지운다. 지금 열려 있는(기록 중인) 세션의 파일과 하위 폴더·다른 확장자 파일은 건드리지 않는다. 설정 값을 바꾸면 곧바로 한 번 정리한다. 지우지 못한 파일(다른 프로그램이 열고 있음 등)은 건너뛰고 다음 주기에 다시 본다. "터미널 출력 기록"이 꺼져 있어도 남은 파일은 정리한다.

## 7. 세션 유지 (tmux)

**적용 조건**: 서버의 `keepSession` 이 켜져 있고, 프로토콜이 SSH 이거나, 로컬이면서 (Windows 가 아니거나 선택한 셸이 `wsl.exe`/`wsl` 인 경우).

**세션 이름**: 서버의 `tmuxName` → 비면 서버 표시 이름 → 비면 로컬 시작 폴더의 마지막 폴더 이름. 점(.), 콜론, 공백, 작은/큰따옴표, `$`, `\`, 백틱의 연속은 하이픈 하나로 바꾸고 앞뒤 하이픈을 제거. 결과가 비었거나 `~`, `/` 이면 `dariterm`.

**접속 직후 셸에 입력하는 한 줄**(앞에 공백 하나 — 히스토리 방지, 끝에 CR): 작은 셸 스크립트를 `sh -c` 로 실행한다. 스크립트의 동작:
1. `tmux` 가 없으면 안내 `● 이 대상에 tmux 가 없어 세션 유지를 쓰지 않습니다 (자동 실행 명령은 실행되지 않음)`(노랑)을 출력하고 **`exit 0`** — 즉시 셸로 돌아가 평소처럼 사용.
2. 같은 이름의 세션이 이미 있으면 그 세션에 **attach**(자동 실행 명령은 실행하지 않음).
3. 없으면 새 세션을 **분리(detached) 상태로 만들고**, 마우스 모드를 켜고, 상태 표시줄을 끈다. 자동 실행 명령이 있으면(줄바꿈은 `; ` 로 바꿈) 그 세션에 키 입력으로 보내고 Enter. 그다음 attach.
4. tmux 를 끝내면(exit) 원래 셸로 돌아온다 — `exec` 하지 않는다(자동 재접속이 새 세션을 계속 만드는 루프 방지).
- 세션 이름과 자동 실행 명령은 셸 인자로 안전하게 따옴표 처리(작은따옴표 이스케이프)해서 전달한다.
- 세션 유지 중인 칸 머리글에 "유지" 배지, 닫을 때·앱 종료 시 안내(ui/panes.md §5, behavior/lifecycle.md §5).

## 7.1 tmux 감지 (로컬 세션 유지 기본값용 — `local.tmuxAvailable`)
- 앱 실행 중 **한 번만 검사해 결과를 기억**한다. 새 로컬 터미널의 세션 유지 기본값(서버 편집, ui/host-editor.md §1.3)에만 쓴다.
- Windows: `wsl.exe` 가 PATH 에 있고 `wsl.exe -e sh -c "command -v tmux"` 가 **5초 안에 성공**하면 true(WSL 안의 tmux). 아니면 false.
- 그 외 OS: PATH 에서 `tmux` 를 찾거나 `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `/opt/local/bin`, `/snap/bin` 에 파일이 있으면 true.

## 8. 입력·크기 전달
- **입력**: 터미널 입력(UTF-8)을 서버 인코딩으로 바꿔 전송. 연결이 없으면 입력은 버려진다(Enter 만 재접속 트리거).
- **크기**: 최근 크기를 기억해 두고 변경 시 프로토콜에 전달(SSH: 창 크기 변경 요청, 텔넷: NAWS, 로컬: 가상 터미널 크기, 시리얼: 없음). 크기를 알리지 못한 상태로 연결되면 기본값 열 120 × 행 32 로 시작하고 열 때 지정한 크기가 있으면 그 값(양수일 때).
- **출력 묶음 전송**: 세션 출력은 프런트로 **12ms 단위로 묶어서** 보낸다(첫 조각이 쌓이면 12ms 타이머를 걸어 그동안의 내용을 한 번에). 묶음 하나는 256KB 를 넘지 않는다(넘으면 12ms 를 기다리지 않고 바로 보낸다).
- **출력 흐름 제어**: 프런트가 아직 처리(`session.ack`)하지 않은 출력이 512KB 를 넘으면 백엔드는 그 세션의 읽기를 멈추고, 128KB 아래로 내려오면 다시 읽는다(원격·로컬 프로세스는 전송 버퍼가 차서 느려진다. 출력은 버리지 않는다). 멈춘 동안 ack 가 3초 동안 오지 않으면 읽기를 다시 연다. 세션을 닫은 뒤에 읽힌 출력과 늦게 끝난 접속 시도의 안내는 보내지 않는다.
- **숨은 세션의 출력**: 보이지 않는 탭의 세션 출력은 약 100ms 단위로 몰아서 터미널에 쓴다. 보이게 되는 순간 밀린 것을 먼저 쓴다.
- **렌더러**: WebGL 을 쓸 수 있으면 WebGL, 아니면(컨텍스트 생성 실패·손실) DOM 렌더러.

## 9. 닫기·종료
- 세션 닫기: 재접속 예약 취소, 로그 닫기, 프로토콜 연결 종료. 사용자가 닫은 세션에서는 끊김 안내·재접속이 없다.
- 앱 종료: behavior/lifecycle.md §5.
- 연결된 세션 수, 세션 유지 중인 연결 수를 종료 확인에 쓴다.
