# SSH 키 만들기·공개 키·서버 등록

> 작성: 2026-11-28, 이 저장소에서 새로 설계한 기능(기존 앱에 없음, D162). 작성 방식: 새 설계.

## 1. 키 만들기 (설정 > 보안 > 저장된 계정 [SSH 키 만들기])

- 창 "새 SSH 키 만들기": 이름(필수, 앞뒤 공백 제거), 종류 **Ed25519(기본, 권장)** / **RSA 4096**, 키 암호(선택). 키 암호를 넣으면 "키 암호 확인" 칸이 나타나고 두 값이 다르면 "키 암호가 서로 다릅니다", [만들기]가 꺼진다.
- 만들면 보관함에 **종류 `key` 계정**이 생긴다: 개인 키는 OpenSSH 형식(`-----BEGIN OPENSSH PRIVATE KEY-----`, 키 암호를 주면 그 암호로 잠김), 키 암호도 함께 저장한다(서버 접속 때 다시 묻지 않게). 사용자 이름은 비운다.
- 공개 키의 주석은 `사용자@컴퓨터`(ssh-keygen 과 같은 모양, 알 수 없으면 주석 없음).
- 만든 직후 토스트 "SSH 키를 만들었습니다: {이름}" 과 함께 공개 키 창을 연다(§2).
- RSA 는 3072·4096 비트만 받는다(IPC 로 다른 값을 주면 오류). 화면은 4096 만 고른다.

## 2. 공개 키 보기 (키 계정 줄의 [공개 키])

- 창 "공개 키 — {이름}": 안내 문구, 공개 키 한 줄(읽기 전용, 누르면 전체 선택), 지문(`SHA256:…`), [닫기] [복사]. 복사하면 토스트 "공개 키를 복사했습니다".
- 공개 키는 보관함의 개인 키에서 다시 만든다. 암호가 걸린 OpenSSH 키는 암호 없이도 공개 키를 읽는다. PEM·PPK 키는 저장된 키 암호로 푼다.
- 비밀번호 계정이면 오류 "SSH 키 계정이 아닙니다".

## 3. 서버에 등록 (SSH 칸 우클릭 "공개 키를 이 서버에 등록…")

- 연결된 SSH 칸에서만 누를 수 있다(시리얼·텔넷·로컬에는 메뉴가 없다).
- 창 "공개 키 등록 — {접속 대상}": 안내, "등록할 키"(보관함의 키 계정만), [SSH 키 만들기](§1 창을 열고, 만들면 그 키를 고른다), **저장된 서버의 칸이면** 토글 "다음 접속부터 이 서버에 이 키로 로그인"(기본 켬). 키 계정이 없으면 "보관함에 SSH 키가 없습니다. 먼저 키를 만드세요." 와 [등록] 꺼짐.
- [등록]: **지금 연결 위에 새 세션 채널**을 열어 명령을 실행한다(다시 인증하지 않는다). 명령은 공개 키 한 줄을 표준 입력으로 받아 `~/.ssh/authorized_keys` 에 넣는다:
  - `umask 077` 로 `~/.ssh`·`authorized_keys` 가 없으면 만든다(있는 것의 권한은 바꾸지 않는다).
  - **종류와 본문**(앞의 두 낱말)이 같은 줄이 이미 있으면 넣지 않는다(주석만 다른 것도 같은 키).
  - 파일 끝에 줄바꿈이 없으면 먼저 줄을 바꾼 뒤 한 줄을 더한다.
  - 로그인 셸이 무엇이든 `sh -c` 로 돌린다. 20초 안에 끝나지 않으면 실패.
- 결과: 넣었으면 토스트 "공개 키를 서버에 등록했습니다", 이미 있으면 "이 키는 이미 서버에 등록되어 있습니다". 실패하면 창에 "서버에 공개 키를 등록하지 못했습니다: {까닭}"(서버의 오류 출력 앞 200자).
- 토글이 켜져 있으면 성공 뒤 그 서버의 인증을 `key`, 계정을 고른 키로 바꿔 저장하고 토스트 "서버 설정을 바꿨습니다: 다음 접속부터 키로 로그인합니다". 원래 쓰던 계정은 지우지 않는다.
- Windows OpenSSH 서버처럼 `sh` 가 없는 서버에서는 실패한다(까닭이 그대로 보인다).
