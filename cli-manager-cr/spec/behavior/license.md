# 사용 용도와 업무용 라이선스

> 작성 방식: 사용자 요청에 따른 신규 기능(원본 앱에 없음, 결정 D78). 작성일 2026-11-14. 상태: **ready**.

## 1. 원칙

- 기능을 잠그지 않는다(신뢰 방식). 알림만 보이고 [확인]을 누르면 그대로 쓴다.
- 판단은 모두 이 PC 안에서 한다. 실행 정보·PC 정보·키를 어디에도 보내지 않는다.
- **개인용은 기한 제한이 없다.** 라이선스 키가 없으면 개인용(또는 업무용 평가)으로 본다.

## 2. 첫 실행 용도 선택

- 언어 선택(behavior/i18n.md §2) 다음, 잠금·처음 설정 화면보다 먼저. `settings.usage` 가 비어 있고 키도 없을 때.
- 제목 "어떻게 사용하시나요?". 선택 두 개:
  - **개인용** — "학습·개인 프로젝트·취미. 무료이고 기한이 없습니다." (기본 선택)
  - **업무용** — "회사·기관·단체의 업무나 영리 목적의 일. 30일 동안 무료로 평가한 뒤 사용자별 업무용 라이선스가 필요합니다."
- 입력칸 "업무용 라이선스 키가 있으면 입력하세요 (선택)". 키를 넣고 [계속]이면 확인해서 맞으면 업무용으로 저장, 틀리면 "라이선스 키가 올바르지 않습니다".
- 안내 "나중에 설정 > 정보에서 바꿀 수 있습니다." 업무용을 고르면 그 시각을 `usageSince` 로 남긴다(평가 시작).

## 3. 사용 형태 판단

| 조건 | 형태 | 정보 화면 문구 | 상태 표시줄 |
|---|---|---|---|
| 키 없음 + 개인용 | 개인용 | 개인용 (라이선스 키 없음) · 기한 없음 | 개인용 |
| 키 없음 + 업무용, 30일 안 | 평가 중 | 업무용 평가 중 (라이선스 키 없음) · n일 남음 | 업무용 평가 n일 |
| 키 없음 + 업무용, 30일 지남 | 평가 끝남 | 업무용 평가 기간이 지났습니다 (라이선스 키 없음) | 업무용 평가 끝남 |
| 키 유효 | 업무용 라이선스 | 업무용 라이선스: {회사} · {번호} · 사용 허가 {n}명 · {버전 범위} · {기한} | 업무용 · {회사} ({n}명) |
| 키 만료·버전 범위 밖·형식 오류 | 라이선스 문제 | 위 + "{날짜}에 만료됨" / "이 버전은 범위 밖" / "라이선스 키가 올바르지 않습니다" | 업무용 라이선스 확인 필요 |

- 남은 날은 올림. 상태 표시줄 글을 누르면 설정 > 정보가 열린다.

## 4. 시작 알림 (한 번 실행에 한 번)

앱이 열린 뒤(잠금 해제·처음 설정 뒤) 한 번만, 다음 중 하나:

- 평가 끝남: 제목 "업무용 라이선스 안내", 본문 "업무용 30일 평가 기간이 지났습니다. 업무에 계속 쓰려면 사용자별 업무용 라이선스가 필요합니다.", 보조 "라이선스 키는 설정 > 정보에서 입력합니다. 이 안내는 시작할 때 한 번만 보이며, 프로그램은 그대로 쓸 수 있습니다." 단추 [확인] 하나.
- 키 만료 / 버전 범위 밖 / 형식 오류: 같은 형식, 본문만 다르다.
- 개인용 + 회사 도메인 가입 PC(Windows AD 또는 Azure AD) + 아직 안 물어봄: 제목 "회사 PC로 보입니다", [업무용으로 바꾸기] / [개인용이 맞습니다] / 닫기. 앞의 둘 중 하나를 고르면 다시 묻지 않는다(`domainNoticeDone`). 닫으면 다음 실행에 다시 묻는다.

## 5. 정보 화면 "사용 형태"

- §3 의 정보 화면 문구(문제가 있으면 경고색).
- 키가 없을 때만 용도 바꾸기 세그먼트 [개인용] [업무용 (30일 평가)].
- 키 입력칸(붙여넣기, Enter 로 적용) + [적용] + 키가 있으면 [키 제거]. 적용하면 "업무용 라이선스를 적용했습니다: {회사}", 틀리면 오류 알림(저장하지 않음).
- 도움말 "키는 이 PC에서만 확인하며 어디에도 보내지 않습니다. 키 내용은 서명되어 있어 고치면 무효가 됩니다."

## 6. 라이선스 키 형식

- `DT1.` + base64url(내용 JSON) + `.` + base64url(Ed25519 서명). 서명 대상은 `DT1.` + 내용 부분 글자 그대로. 붙여 넣을 때 섞인 공백·줄바꿈은 무시한다.
- 내용: `v`(1), `id`(라이선스 번호), `org`(회사·사용권자), `seats`(사용 허가 수), `ver`(최대 주 버전, 0=모든 버전), `exp`(만료일 `YYYY-MM-DD`, 그날까지 유효, 빈 값=기한 없음), `iat`(발급일), `email`(선택).
- 3년·5년 같은 기간제는 `exp` 를 발급일 + 기간으로 넣는다. 영구 라이선스는 `exp` 를 비운다.
- 앱에는 **공개키만** 들어 있다. 키를 만들 수 있는 비밀키는 발급하는 쪽만 가진다(앱을 분석해도 키를 만들 수 없다). 내용을 한 글자라도 바꾸면 서명이 맞지 않아 무효다.
- 키는 `settings.licenseKey` 에 저장한다(비밀값이 아님).
