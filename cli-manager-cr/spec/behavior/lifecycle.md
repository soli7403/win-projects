# 앱 수명주기 — 시작·잠금·레이아웃 복원·창·종료·업데이트

> 작성 방식: 기존 앱 동작 열람. 작성일 2026-11-10. 상태: **draft**.

## 1. 시작
1. 데이터 폴더를 열고(data/sync-backup.md §1) store·vault 를 읽는다. 읽기에 실패하면(깨짐, data/sync-backup.md §1) 앱이 오류를 보이고 시작하지 않는다.
2. 창을 연다(§4). 시작 후 백그라운드 작업 3개를 돌린다: 자동 잠금 검사(§2), 업데이트 확인(§6), git 동기화 주기(data/sync-backup.md §5.5).
3. 화면 쪽 시작 흐름은 ui/shell.md §6.

## 2. 자동 잠금
- **20초마다** 확인: 설정 "자동 잠금 (분)"이 0 보다 크고 볼트가 열려 있고, 사용자의 **마지막 키보드·마우스 입력 이후 경과 시간**이 그 분 이상이면 볼트를 잠근다(열린 세션은 유지, 잠금 화면이 위에 덮임). 경과 시간은 운영체제의 마지막 입력 시각을 쓴다(Windows: 마지막 입력 정보 조회).
- 설정 화면 도움말은 "Windows를 잠그거나 절전하면" 잠근다고 안내한다 → **구현 결정(D6)**: 안내 문구와 일치하도록 Windows 세션 잠금·절전 진입 알림에서도 볼트를 잠근다. (기존 앱은 유휴 시간만 검사하므로 이 부분은 의도적 개선; 구현이 어려우면 도움말 문구에서 해당 구절을 빼고 `decisions.md` 에 기록.)
- **Windows 잠금 판정**(2026-11-27, D154): 20초 검사에서 이 앱이 도는 **Windows 세션의 잠금 상태**를 읽는다 — 잠김이면 볼트를 잠근다. 화면 보호기만 켜진 상태(다시 시작할 때 로그온 화면을 표시하지 않음)는 잠금이 아니다. 세션 상태를 알 수 없는 환경(서비스·일부 원격)에서만 예전 추정(입력 데스크톱을 열 수 없고 접근 거부이면 잠김)을 쓴다. 화면 보호기는 별도 데스크톱에서 돌아 예전 추정만으로는 잠긴 것으로 잘못 볼 수 있었다. Windows 밖에서는 이 판정이 없다(유휴 시간만).
- 터미널 출력만으로는 "사용 중"으로 치지 않는다(입력 기준).

## 3. 탭·분할 레이아웃 저장/복원 (설정 "마지막 화면 배치 복원")

### 3.1 저장
- 탭 목록, 활성 탭, 세션 상태(연결됨 등)가 바뀔 때마다 **0.3초 모아서** 저장 요청을 보낸다. **복원이 끝나기 전에는 저장하지 않는다**(시작 직후 빈 상태로 덮어쓰지 않도록). 설정이 꺼져 있으면 저장하지 않는다. 직전에 저장한 내용과 **JSON 이 같으면 다시 저장하지 않는다**(세션 상태만 바뀐 경우).
- 저장 형식은 data/store.md §5. 규칙:
  - 칸: 빈 칸 → `{type: pane, empty: true}`. 세션이 있는 창은 **저장된 서버의 세션**이면 `{hostId}`, **로컬 세션**이면 `{local: {cwd}}`(세션 대상 문자열에서 `로컬 · ` 접두를 뗀 값). 그 외(**즉석 SSH/텔넷**은 비밀번호가 필요하므로) **저장하지 않음**(칸 제외).
  - 분할: 저장되는 자식만 남기고, 하나만 남으면 그 자식이 분할을 대신, 없으면 분할 전체 제외. 크기는 남은 자식 합이 100 이 되도록 비례 조정.
  - 탭: 저장할 칸이 없는 탭은 제외. 제목(사용자 지정이 있으면), 동시 입력 여부(켜진 경우만). 활성 탭 인덱스는 저장되는 탭 기준.
- 비밀번호·화면 내용은 저장하지 않는다.

### 3.2 복원
- **볼트가 열린 뒤 한 번만**(앱을 켠 뒤 처음 열렸을 때). 설정이 꺼져 있거나 저장된 탭이 없으면 아무것도 하지 않는다.
- 탭마다, 칸을 위에서부터 차례로 만든다. 저장된 서버 id 가 **지금 서버 목록에 있으면** 그 서버로 접속(세션 열기), 로컬이면 저장된 시작 폴더로 로컬 세션을 열고, 빈 칸이면 빈 칸으로 둔다. **서버가 삭제되었거나 접속 시작이 실패한 칸은 제외**하고 분할 구조를 같은 규칙으로 줄인다(크기 재정규화).
- 복원된 탭은 모두 새 id, 첫 칸이 포커스, 제목·동시 입력 상태 복원. 활성 탭은 저장된 인덱스(범위를 넘으면 마지막).
- 복원 후 비어 있는 결과(모든 칸 제외)면 해당 탭은 만들지 않는다.

## 4. 창
- 제목 "DariTerm", 최소 크기 900×560, 기본 크기 1440×900, 운영체제 기본 프레임(자체 제목 버튼 없음).
- **창 상태 기억**(설정 "프로그램 창 크기·위치 기억", 기본 켬): 앱을 닫을 때 크기·위치·최대화 여부를 저장(data/sync-backup.md §4). **최대화 상태로 닫으면 일반 상태의 크기·위치를 보존**하고 최대화 표시만 켠다.
- **시작 시 복원**: 저장된 크기(w ≥ 400, h ≥ 300 일 때만 유효)로 열고 최대화였으면 최대화로 시작. 화면이 준비되면 위치를 복원한다: 저장된 위치가 **어느 모니터에도 걸치지 않으면 주 화면 가운데**로 연다. 판단: 연결된 모든 모니터에 대해 `(저장 x + 80 > 모니터 왼쪽)`, `(저장 x < 모니터 오른쪽)`, `(저장 y ≥ 모니터 위쪽 − 10)`, `(저장 y < 모니터 아래쪽)` 을 모두 만족하는 모니터가 **하나라도 있으면 "보인다"** 로 본다(왼쪽 위 약 80×30 영역이 화면과 겹치는지). 기존 앱은 모니터 크기만 쓰고 좌표 오프셋을 무시했지만, **실제 모니터 영역(좌표 포함)을 쓰는 것이 정확**하므로 그렇게 구현해도 된다. 유효한 저장이 없으면 가운데. 설정이 꺼져 있으면 항상 가운데·기본 크기.
- **[기본 크기로]**: 최대화 해제 → 1440×900 → 가운데 → 저장 상태를 `{w:1440, h:900}` 로 덮어쓴다.
- 전체 화면 전환(F11)은 **최대화 ↔ 복원 토글**이다.

## 5. 종료
- 창을 닫을 때 **연결된 세션이 하나라도 있으면** 확인 대화상자(운영체제 질문 대화상자): 제목 "DariTerm", 본문 `연결된 세션 {n}개가 있습니다. 모두 닫고 종료할까요?` + (세션 유지 중인 연결이 있으면 빈 줄 뒤에) `세션 유지(tmux) 중인 창 {k}개는 앱을 닫아도 안의 프로그램이 계속 실행되고, 다시 열면 그 화면에 그대로 붙습니다. 완전히 끝내려면 그 창에서 exit 를 입력하세요.`, 버튼 [종료] [취소](기본값·취소 키 = 취소). 취소하면 종료하지 않는다.
  - **구현 주의(Windows)**: 앱 런타임(Wails)의 Windows 질문 대화상자는 지정한 버튼 이름을 쓰지 않고 **시스템 버튼("예(Y)"/"아니요(N)")으로 표시하며, 선택 결과로 `"Yes"` / `"No"` 문자열을 돌려준다**(비 Windows 는 지정한 이름을 돌려줄 수 있다). 따라서 "종료 선택"의 판정은 반환값이 `"종료"`, `"Yes"`, `"예"`, `"예(Y)"` 중 하나인 경우로 한다. 반환값이 이들 중 하나도 아니거나 오류면 취소로 본다. (이 판정이 틀리면 확인에서 "예"를 눌러도 앱이 종료되지 않는다 — 통합 점검에서 발견된 결함.)
  - 이 판정은 반드시 **순수 함수로 분리해 단위 테스트**한다.
  - **종료 정리**: 종료를 확인하면 모든 세션 정리(로컬 셸 자식 프로세스 종료, SSH 연결 닫기)를 시도하되 **최대 약 3초만 기다리고**, 그래도 끝나지 않으면 정리를 두고 종료를 우선한다(앱이 종료되지 않는 것이 더 큰 결함). 단 **로컬 셸 자식 프로세스는 앱 종료 뒤에 남지 않아야 한다**(종료 때 강제 종료하거나 앱과 수명을 묶는다).
- 종료가 진행되면 창 상태를 저장하고, 모든 세션을 닫고, store 를 즉시 저장한다.

## 6. 새 버전 확인

> **D80 (2026-11-14): 지금은 꺼져 있다.** 배포 저장소 주소(G_cszUpdateRepo)가 정해진 빌드에서만 동작한다. 주소가 없으면 백그라운드 확인을 하지 않고, 설정 > 정보의 업데이트 항목([업데이트 자동 확인]·[업데이트 확인])을 감춘다(app.info.updateEnabled=false). 공개 릴리스 저장소가 생기면 주소를 넣어 켠다.
- **시작 5초 뒤** 첫 확인, 이후 **12시간마다**. 설정 "업데이트 자동 확인"이 꺼져 있으면 그 주기 확인은 건너뛴다(주기 자체는 계속 돌며 켜면 다음 주기에 반영). 설정 화면의 [업데이트 확인]은 설정과 무관하게 실행.
- 확인: 배포 저장소(`owner/name`)의 최신 릴리스를 조회한다. 저장소는 **빌드 시 지정**하거나 환경 변수 `DARITERM_UPDATE_REPO`(API 주소는 `DARITERM_UPDATE_API`, 시험용)로 지정. **지정이 없으면** 결과 `unconfigured`(확인 안 함). 요청은 `GET {API}/repos/{저장소}/releases/latest`, 헤더 `User-Agent: DariTerm/{현재 버전}`, `Accept: application/vnd.github+json`, 타임아웃 10초(전체 15초). 사용자 정보는 보내지 않는다. 네트워크 실패·200 이외·해석 실패는 `error`(조용히 무시, 폐쇄망 대응).
- **버전 비교**: 태그 앞의 `v` 와 `-`/`+` 뒤 접미를 떼고 숫자 3개(major.minor.patch, 부족하면 0)로 비교한다. 최신 > 현재면 `newer`(버전은 `v` 뗀 문자열, 릴리스 페이지 URL 포함), 아니면 `latest`.
- `newer` 이면 상태 표시줄의 "새 버전 {버전}" 버튼을 위해 기억하고 "새 버전 발견" 이벤트를 보낸다. **처음 발견한 버전이거나 수동 확인이면 안내 토스트도 띄운다**: `새 버전 {버전} 이 있습니다 (상태 표시줄을 눌러 확인)`. 마지막으로 안내한 버전은 데이터 폴더의 `update.json`(`{notified: 버전}`)에 기록해 같은 버전은 다시 안내하지 않는다.

### 6.1 Microsoft Store 설치본의 새 버전 확인 (2026-11-23, D115)

- **Windows 에서 Microsoft Store 로 설치한 실행**(패키지된 앱)은 새 버전을 배포 저장소가 아니라 **Microsoft Store 에 묻는다**. 설치 파일로 설치했거나 빌드 폴더에서 바로 실행한 경우, Windows 가 아닌 OS 는 해당하지 않는다(위 §6 의 규칙 그대로 — 배포 저장소가 없으면 꺼짐).
- 스토어 설치본에서는 설정 > 정보의 업데이트 항목이 보인다. 토글 설명은 "시작할 때와 12시간마다 Microsoft Store에 새 버전이 있는지 확인합니다. …" 로 바뀐다. 주기(시작 5초 뒤, 12시간마다)·자동 확인 끄기·[업데이트 확인]·처음 발견한 버전만 알림은 §6 과 같다.
- 확인: 스토어에 이 앱의 업데이트 목록을 묻는다(시한 30초). 이 앱(패키지 이름 `YangHunLee.DariTerm`)의 업데이트가 있으면 `newer`(버전은 스토어의 네 자리에서 끝의 `.0` 을 뗀 것, 주소는 스토어 제품 페이지 `ms-windows-store://pdp/?productid=9N8WBPMRNBWV`, `store: true`), 없으면 `latest`, 스토어가 답하지 않으면 `error`. 스토어는 설치된 것보다 새 버전만 알려 주므로 앱이 버전을 비교하지 않는다.
- **업데이트 확인(설치)**: 상태 표시줄의 "새 버전 {버전}" 버튼(도움말 "Microsoft Store 업데이트 확인 창 열기")을 누르면 Windows 의 업데이트 확인 창이 앱 창 위에 뜬다. 사용자가 확인하면 Windows 가 내려받아 설치하며, 그 과정에서 앱이 닫힐 수 있다(시한 60분). 창이 떠 있는 동안 버튼을 다시 눌러도 겹쳐 띄우지 않는다.
  - 끝난 뒤 토스트: 설치됨 "업데이트를 설치했습니다. 앱을 다시 시작하면 새 버전으로 실행됩니다"(ok) / 사용자가 취소 "업데이트를 취소했습니다"(info) / 그사이 업데이트가 없어짐 "최신 버전입니다"(ok, "새 버전" 버튼도 지운다).
  - 확인 창을 띄우지 못했거나 Windows 가 오류 상태를 알려 주면(Wi-Fi 필요, 배터리 부족 등) 오류 토스트를 내고 **Microsoft Store 의 제품 페이지를 대신 연다**(거기서 직접 업데이트할 수 있다).
- 앱이 스토어에 보내는 것은 Windows 의 스토어 기능이 보내는 것뿐이다(앱 식별 정보). 서버 목록·IP·계정 정보는 보내지 않는다.
- 열려 있는 세션이 있을 때 설치를 확인하면 Windows 가 앱을 닫으면서 세션이 끊긴다. 확인 창에서 취소하면 아무 일도 일어나지 않는다.

- 업로드 파일 접두 `dt-`, 백업 확장자 `.dtbackup`, IPC 채널 이름, 로고는 새로 정한다.
