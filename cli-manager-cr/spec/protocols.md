# 프로토콜별 동작 — SSH · SFTP · 텔넷 · 시리얼 · 로컬 터미널

> 작성 방식: 기존 앱 동작 열람(사용자에게 관찰되는 동작·한도). 작성일 2026-11-10. 상태: **draft**. 세션 수명주기(재접속 등)는 behavior/session.md.

## 1. 공통

- 모든 프로토콜은 세션 출력을 바이트로 받아 서버 인코딩(§1.1)으로 해석하고, 입력(UTF-8 문자열)은 같은 인코딩 바이트로 보낸다. 로컬 터미널은 항상 UTF-8.
- 접속 상태 메시지는 **터미널 화면 안에** 짧은 줄로 보인다(§behavior/session.md §3).

### 1.1 문자 인코딩
| 설정값 | 해석 |
|---|---|
| utf-8 | UTF-8. 청크 끝에 잘린 멀티바이트 글자는 다음 데이터와 이어 붙여 해석. 잘못된 바이트는 `�` 로 치환 |
| cp949, euc-kr | EUC-KR(CP949) |
| shift_jis | Shift_JIS |
| latin1 | ISO-8859-1 |
- 비-UTF-8 인코딩에서 잘린 글자는 다음 청크로 넘긴다. 남은 바이트가 4바이트를 넘으면(잘린 글자가 아니라 잘못된 바이트) 버리지 않고 `�` 하나로 치환하고 계속한다.
- 입력 변환 실패 시 원본 UTF-8 바이트를 그대로 보낸다.

## 2. SSH

### 2.1 접속 순서
1. 점프 호스트가 있으면 먼저 그 호스트에 접속(§2.4). 없으면 대상에 직접 TCP 접속. 연결 제한시간 **20초**.
2. 호스트 키 확인(§2.3)과 사용자 인증(§2.2).
3. 셸 세션을 열고 **PTY 요청**: 터미널 종류=서버 설정의 `termType`(비면 `xterm-256color`), 크기=현재 터미널 크기(각각 최소 2), 에코 켬, 속도 14400.
4. 셸 시작, 표준 출력·표준 오류를 함께 화면 출력으로 보낸다(읽기 단위 32KB).
5. 포트 포워딩 설정(§2.5).
6. 셸 종료 또는 SSH 연결 종료 시 세션 종료 처리(연결 종료 이유 "연결이 종료되었습니다"; 사용자가 닫은 경우는 이유 없음).

### 2.2 사용자 이름과 인증
- **사용자 이름**: 서버 설정 값 → 비면 연결된 계정(볼트)의 사용자 이름 → 그래도 비면 "사용자 이름 입력" 요청(취소·빈 값이면 접속 실패 "사용자 이름이 입력되지 않았습니다").
- 연결된 계정(`credentialId`)이 있으면 볼트에서 비밀을 읽는다(항목이 없으면 비밀 없이 진행). 볼트가 **잠겨 있으면** 아래 세션 사본을 쓰고, 사본도 없으면 접속하지 않고 잠금 해제를 기다린다(session.md §4).
- **세션 사본**(2026-11-17): 세션은 접속에 성공할 때 쓴 계정(대상과 점프 서버마다 사용자 이름·비밀번호·개인 키·키 암호 — 볼트에서 읽은 것과 사용자가 입력해 **인증에 성공한** 것, 저장 여부와 무관)을 **그 세션의 메모리에만** 사본으로 둔다. 다시 접속할 때 볼트 값을 먼저 채우고, 비어 있는 필드는 사본으로 채운다(볼트가 열려 있으면 그사이 바꾼 계정이 반영되고 사본도 갱신된다). 세션을 닫으면 사본을 지운다(개인 키 바이트는 0 으로 덮어씀). 새로 연 세션은 사본이 없다. 볼트가 잠겨도 열린 세션을 유지하는 정책(lifecycle §2)과 같은 위험 수준으로 본다. 잠긴 볼트를 OS 계정(DPAPI) 등으로 몰래 여는 방법은 쓰지 않는다.
- **볼트가 잠긴 동안에는 어떤 질문 창도 띄우지 않는다**(2026-11-17): 사용자 이름·비밀번호·키 암호·키보드-인터랙티브·호스트 키 요청이 필요해지면 접속을 멈추고 잠금 해제를 기다린다(session.md §4). 잠금 화면 뒤의 창에 자동으로 답하지 않는다. 볼트를 만들지 않았으면 지금처럼 묻는다.
- **인증 방법을 다음 순서로 시도**한다.
  1. 계정에 개인 키가 있으면 공개 키 인증. 키가 암호로 보호되어 있고 키 암호(passphrase)가 저장돼 있지 않거나 틀리면 "키 암호 입력" 요청을 **최대 3번**. 끝내 못 읽으면 터미널에 안내 "개인 키를 읽을 수 없습니다: {오류} (PPK 키는 PuTTYgen 에서 OpenSSH 형식으로 내보내 주세요)" 를 보이고 이 방법은 건너뜀.
  2. 인증 방식이 `agent` 또는 `key` 이면 SSH 에이전트가 있을 때 에이전트 인증. **Windows 에서는 OpenSSH 에이전트의 이름 있는 파이프(`\.\pipe\openssh-ssh-agent`)에만 연결한다 — 연결할 수 없으면 이 방법은 건너뛴다. (화면 문구에는 "Pageant" 가 적혀 있으나 Pageant 에는 연결하지 않는다 — 알려진 불일치, 문구는 명세 그대로 둔다.)** 그 외 OS 는 `SSH_AUTH_SOCK`(1차 범위 밖).
  3. 계정에 비밀번호가 있으면 비밀번호 인증.
  4. 키보드-인터랙티브: 질문이 **하나이고 에코가 없고 질문에 "pass" 가 들어 있으면** 비밀번호 요청 화면으로 처리(아래), 그 외는 "추가 인증" 요청(서버가 준 안내문·질문·에코 여부 그대로).
  5. 비밀번호 직접 입력: 서버 이름·사용자 이름이 들어간 안내 `{사용자}@{호스트} 비밀번호` 로 비밀번호 요청. **실패하면 최대 4번까지 다시 묻는다.** 두 번째 시도부터 요청에 "실패" 표시(failed).
- 비밀번호 요청 화면은 "암호화해 저장" 체크를 허용한다(allowSave). 인증에 **성공했을 때만** 저장 처리한다: 볼트가 열려 있고 저장된 서버일 때, 서버 별칭 이름의 비밀번호 항목을 저장(기존 계정이 있으면 갱신)하고 서버의 계정 연결을 갱신. 서버 사용자 이름이 비어 있었으면 입력한 사용자 이름을 채우고, 인증 방식이 `ask` 였으면 `password` 로 바꾼다. 저장 후 "데이터 변경됨" 이벤트를 보내고 터미널에 안내 "비밀번호를 암호화해 저장했습니다".
- 점프(베스천) 구간의 비밀번호는 **대상 서버의 계정을 덮어쓰지 않는다**: 저장된 서버를 베스천으로 쓸 때는 저장하지 않고, "직접 입력" 베스천은 이름 `{대상 표시 이름} 경유 서버` 의 별도 항목에만 저장하고 대상 서버의 `jumpDirect.credentialId` 만 갱신(즉석 연결(`adhoc-`)은 저장 안 함).

### 2.3 호스트 키 확인
- `host:port` 를 키로 `knownHosts` 를 조회한다. **지문(SHA256)** 이 같으면 통과.
- 처음 보는 서버이거나 지문이 다르면 "호스트 키" 요청을 띄운다(처음이면 changed=false, 바뀌었으면 changed=true + 이전 지문). 사용자가 거부하면 접속 실패 "호스트 키를 승인하지 않았습니다 (host key rejected)". 승인하면 knownHosts 에 기록(키 종류, 지문, 시각).

### 2.4 점프 호스트
- 서버의 `jumpHostId` 가 서버 id 이면 그 서버로, 값이 `direct` 이면 `jumpDirect` 정보(주소·포트·사용자·인증 방식·계정)로 합성한 경유 서버으로 연결한다(포트가 0 이면 22, 표시 이름은 `{대상 별칭} 베스천`).
- 점프 호스트 자신도 점프 호스트를 가질 수 있어 **재귀**로 이어진다. **점프 호스트가 4단계를 넘게 이어지면(대상 기준 깊이 5)** 오류 "경유 서버 체인이 너무 깁니다". 찾을 수 없으면 "경유 서버를 찾을 수 없습니다".
- 점프 중 안내 "경유 서버 {표시 이름} 경유 중..." 를 터미널에 보이고, 베스천에 접속한 뒤 그 연결 위에서 대상으로 TCP 연결을 열어 SSH 를 시작한다(대상 연결 제한시간 20초). 세션을 닫으면 대상과 모든 점프 연결을 함께 닫는다.
- 점프 호스트의 연결 유지(keepalive)는 대상 서버의 설정값을 따른다.

### 2.5 포트 포워딩
- 서버의 `forwards` 마다: 바인드 주소가 비면 `127.0.0.1`.
  - **L(로컬)**: 이 PC 의 바인드 주소:포트에서 대기 → 연결이 오면 SSH 연결을 통해 대상 호스트:포트로 중계.
  - **R(원격)**: 서버 쪽에서 바인드 주소:포트로 대기 → 연결이 오면 이 PC 에서 대상 호스트:포트로 중계.
- 설정 성공 시 터미널에 "포워딩 {바인드}:{포트} → {대상}", 실패 시 "포트 포워딩 {L|R}{포트} 실패: {오류}" 를 보이고 다음 항목으로 계속한다. 세션이 끝나면 모든 대기 소켓을 닫는다.

### 2.6 연결 유지(keepalive)
`keepaliveSec` 가 0 보다 크면 그 간격으로 `keepalive@openssh.com` 요청을 보낸다. **연속 4번 실패하면 연결을 닫는다**(세션 종료 처리 → 자동 재접속 규칙 적용). 요청의 응답이 keepalive 간격 안에 오지 않으면 그 요청은 실패로 센다(상대가 조용히 사라져도 약 4 × 간격 안에 끊김을 알아챈다). 연결을 닫으면 keepalive 도 바로 멈춘다.

## 3. SFTP (SSH 세션 위)

- SSH 로 **연결된** 세션에서만 사용 가능. 아니면 오류 "SSH로 연결된 세션에서만 사용할 수 있습니다". SSH 연결이 바뀌면(재접속) SFTP 클라이언트를 새로 만든다. 세션을 닫으면 캐시를 정리한다.
- 홈 경로는 서버의 `.` 의 실제 경로(세션마다 한 번 조회해 기억). 경로가 `~` 이거나 `~/…` 로 시작하면 홈으로 치환한다.
- **목록**: 경로가 비면 `~`. 실제 경로로 정규화(실패하면 입력 경로 그대로). **폴더 먼저, 그다음 이름 오름차순(대소문자 무시)**. 항목: 이름, 전체 경로, 폴더 여부, 링크 여부(링크이면 대상이 폴더인지 다시 확인해 폴더 여부를 갱신), 크기, 수정 시각(ms), 권한(하위 9비트 숫자), 권한 문자열(`drwxr-xr-x` 형식, 첫 글자 d/l/-).
- **삭제**: 폴더는 안의 내용까지 재귀 삭제. 항목 중 하나라도 실패하면 즉시 오류로 중단.
- **전송 큐**: 업로드·다운로드는 **세션마다 한 번에 하나씩** 순서대로 처리한다.
- **업로드**: 로컬 파일은 원격 폴더 아래 같은 이름으로, 로컬 폴더는 원격에 폴더를 만들고(이미 있어도 무시) 안의 내용을 재귀로 올린다. 파일마다 전송 항목(대기→진행→완료/오류)을 만들고 진행률 이벤트를 **150ms 이상 간격**으로 보낸다. 한 파일이라도 실패하면 거기서 중단하고 오류.
- **다운로드**: 원격 파일은 로컬 폴더 아래 같은 이름으로, 원격 폴더는 로컬에 폴더를 만들고 재귀로. **개별 파일 실패는 그 전송 항목에만 오류로 표시하고 계속**한다(전체는 중단하지 않음).
- **미리보기**: 이미지 확장자(png, jpg, jpeg, gif, webp, bmp, svg)는 **20MB 이하**일 때 `data:` URL(base64)로, 그 외 파일은 **512KB 이하**이고 **NUL 바이트가 없을 때** 텍스트로. 조건에 맞지 않으면 "미리보기 없음".
- **로컬 앱으로 편집**: 원격 파일을 임시 폴더(`<임시>/dariterm-edit/<무작위>/<파일명>`)에 내려받고(전송 항목 표시) 기본 프로그램으로 연다. 이후 **700ms 간격으로 수정 시각을 확인**해, 저장되어 시각이 바뀌면 0.4초 기다린 뒤 서버로 다시 올린다(성공 토스트 `{파일명} 저장됨 → 서버에 업로드 완료`, 실패 토스트 `업로드 실패: {오류}`). 세션이 사라지거나 **12시간**이 지나면 감시를 끝낸다.
- **붙여넣기용 올리기(uploadForPrompt)**: 설정 `uploadDir`(기본 `~/.dariterm/uploads`)를 홈 치환해 폴더를 만들고(상위 포함) 올린다. 파일 이름 규칙:
  - 클립보드 이미지: `dt-YYYYMMDD-HHMMSS-<무작위 4자리 16진>.png` (이 PC 클립보드의 이미지를 PNG 로 저장해 올림)
  - 버퍼 데이터: 같은 형식, 확장자는 주어진 이름의 확장자(없으면 `.png`)
  - 파일: `dt-YYYYMMDD-HHMMSS-<4자리>-<원래 이름>` (원래 이름의 공백, `'`, `"`, `` ` ``, `$`, `\` 는 `_` 로 바꿈). 폴더는 구조 그대로 올림.
  - 올린 뒤 백그라운드로 **오래된 파일 정리**: 설정 `uploadCleanupDays` > 0 이면 업로드 폴더에서 이름이 `dt-` 로 시작하고 수정 시각이 그 일수보다 오래된 파일만 삭제.
- **로컬 세션용 저장(saveForPrompt)**: 파일이면 원래 경로를 그대로 돌려준다. 이미지(클립보드/버퍼)면 이 PC 의 업로드 폴더(홈 치환, 권한 소유자 전용으로 생성)에 같은 규칙의 이름(`dt-…`)으로 저장하고 그 경로를 돌려준다. 같은 방식으로 오래된 `tg-` 파일 정리.
- **클립보드(Windows) 세부**:
  - 텍스트: 앱 런타임의 클립보드 텍스트 읽기/쓰기.
  - 파일 목록: 탐색기에서 복사한 파일(CF_HDROP 형식)의 경로들. **디스크에 실제로 존재하는 파일만** 남기고, 하나라도 남으면 종류는 `files`. 붙여넣기(Ctrl+V·오른쪽 클릭)마다 판정하므로 별도 프로세스 없이 바로 읽는다(파일 목록 형식이 없으면 클립보드를 열지도 않는다).
  - 이미지 유무: 클립보드에 비트맵(CF_DIB 형식)이 있는지.
  - 이미지 → PNG: 숨긴 `powershell.exe -NoProfile -NonInteractive -STA` 로 `System.Windows.Forms.Clipboard.GetImage()` 를 PNG 로 저장해 base64 로 받는다(드문 경로라 느려도 됨). 이미지가 없으면 오류 "클립보드에 이미지가 없습니다", 읽기 실패면 "클립보드 이미지를 읽지 못했습니다".
  - `clip.info` 판정 순서: 존재하는 파일 목록 → 텍스트(비어 있지 않음) → 이미지 → `empty`.
  - 비 Windows 에서는 파일 목록·이미지를 지원하지 않는다(텍스트만, 1차 범위 밖).

## 4. 텔넷

- TCP 접속(제한시간 15초). 서버가 보내는 **IAC 명령**을 해석해 데이터에서 제거하고 최소한의 협상을 한다.
  - 서버의 `WILL ECHO`, `WILL SUPPRESS-GO-AHEAD` 에는 `DO` 로 응답, 그 외 `WILL` 에는 `DONT`.
  - 서버의 `DO NAWS`(창 크기)에는 `WILL NAWS` 로 응답하고 현재 크기를 하위 협상으로 즉시 전송, 이후 크기가 바뀔 때마다 전송(16비트 열·행). `DO TERMINAL-TYPE` 에는 `WILL`, 서버가 종류를 물으면(`SEND`) 서버 설정의 터미널 종류(비면 `xterm-256color`)를 보낸다. 그 외 `DO` 에는 `WONT`.
  - 데이터의 `IAC IAC` 는 바이트 255 하나로 해석.
- 보낼 때 입력의 바이트 255 는 `IAC IAC` 로 이스케이프한다.
- 연결이 끊기면 이유 "연결이 종료되었습니다"(사용자가 닫은 경우는 이유 없음).

## 5. 시리얼

- 장치 열기: 속도(0 이면 9600), 데이터 비트(0 이면 8), 패리티(none/even/odd/mark/space), 정지 비트(1/1.5/2). 흐름 제어 설정값(`flowControl`)은 저장하지만 현재 동작에 쓰지 않는다(알려진 한계). 서버 편집 화면에 이 사실을 안내한다(ui/host-editor.md §1). 열기 실패 시 오류 메시지는 `{장치}: {원인}`.
- 읽기 단위 4KB. 포트가 닫히면 이유 "포트가 닫혔습니다"(사용자가 닫은 경우는 이유 없음). **시리얼은 자동 재접속을 하지 않는다**.
- 읽기는 50ms 시한으로 돌아와 그사이 쌓인 로컬 에코를 바로 내보낸다(장치가 아무것도 보내지 않아도 입력한 글자가 즉시 보인다).
- 쓰기: 입력의 CR(`\r`)을 **Enter 전송값**(CR/LF/CRLF)으로 바꿔 보낸다. **로컬 에코**가 켜져 있으면 보낸 내용을 그대로 화면에도 출력하되 CR 과 CRLF 는 화면에서 줄바꿈(`\r\n`)으로 보이게 한다.
- 터미널 크기 변경은 시리얼에 아무 영향이 없다.
- **장치 목록**: 포트 이름 + (제품명이 있으면 ` · {제품명}`)을 라벨로. 상세 열거가 실패하거나 비면 단순 목록으로 대체. 실패 시 빈 목록.

## 6. 로컬 터미널

- **셸 목록**(첫 항목이 기본): Windows 는 `powershell.exe`("Windows PowerShell"), `cmd.exe`("명령 프롬프트 (cmd)"). `pwsh.exe` 가 PATH 에 있으면 두 번째로 `pwsh.exe`("PowerShell 7")를 넣고, `wsl.exe` 가 있으면 마지막에 `wsl.exe`("WSL (Linux)") 추가. 비 Windows 는 환경변수 SHELL(없으면 `/bin/sh`)을 기본으로, `/etc/shells` 에 있고 실제 존재하는 셸을 이어 붙인다(라벨=파일 이름).
- **시작**: 셸 지정이 없으면 기본 셸, 실행 파일은 PATH 에서 절대 경로로 찾는다. 인자: PowerShell 계열은 `-NoLogo`, Unix 의 bash·zsh·fish·sh·ksh·tcsh·csh 는 `-l`(로그인 셸), 그 외 없음.
- **시작 폴더**: 지정이 없으면 홈. `~` 로 시작하면 홈으로 치환. **폴더가 없거나 폴더가 아니면 홈으로 열고** 터미널에 안내 "시작 폴더({지정값})가 없어 홈 폴더에서 엽니다"(지정이 있었던 경우에만).
- **환경 변수**: 현재 환경 + `TERM=<서버 설정 터미널 종류, 비면 xterm-256color>`, `COLORTERM=truecolor`, `TERM_PROGRAM=DariTerm`.
- 가상 터미널(Windows ConPTY 등)의 크기를 설정하고(각각 최소 2) 출력은 32KB 단위로 읽는다. 입출력은 UTF-8.
- **종료**: 셸 프로세스가 끝나면 이유 "셸이 종료되었습니다"(종료 코드가 0 이 아니면 ` (코드 N)` 덧붙임). 사용자가 닫을 때는 프로세스를 강제 종료.
- 로컬 세션은 SFTP 불가이지만 이미지 붙여넣기는 가능하다(§3 로컬 저장).
