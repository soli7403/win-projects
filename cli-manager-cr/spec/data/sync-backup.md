# 데이터 형식 — 저장 파일 규칙, 백업, git 동기화

> 작성 방식: 기존 앱 열람 (호환·동작에 필요한 사실). 작성일 2026-11-10. 상태: **draft**.

## 1. 데이터 폴더와 파일

- 데이터 폴더: 환경 변수 `DARITERM_DATA`(없으면 옛 `TERMGO_DATA`)가 있으면 그 경로, 없으면 `<사용자 설정 폴더>\DariTerm\data`(Windows: `%APPDATA%\DariTerm\data`). 없으면 만든다(권한 소유자 전용).
  - **이전 (2026-11-12, 제품 이름 TermGo → DariTerm)**: 새 폴더가 없고 옛 `<사용자 설정 폴더>\TermGo\data` 가 있으면 시작할 때 통째로 복사해 온다. 임시 폴더에 다 복사한 뒤 이름을 바꾸므로, 실패하면 새 폴더를 만들지 않고 시작 오류가 난다. 옛 폴더는 백업으로 그대로 둔다. 새 폴더가 이미 있으면 복사하지 않는다.
  - 동기화 형식 이름·파일 이름, 백업 파일 안의 앱 식별자, 볼트 암호화의 연관 데이터 문자열은 호환을 위해 이름 변경 전 값(`termgo…`)을 그대로 쓴다.
- 파일 목록: `store.json`(data/store.md), `vault.json`(data/vault.md), `window.json`(창 상태), `update.json`(마지막 안내 버전), `sync-base.json`·`sync-repo/`(git 동기화), `logs/`(세션 로그).
- **저장 방식(JSON 파일 공통)**: 들여쓰기 2칸으로 직렬화 → 기존 내용을 `<파일>.bak` 으로 복사 → `<파일>.tmp` 에 쓰고 이름을 바꿔 교체. 파일 권한은 소유자 전용. 읽을 때 본 파일이 읽히지 않거나 JSON 이 깨져 있으면 `.bak` 을 시도하고, 둘 다 없으면 "없음".
- **"없음"과 "깨짐"을 구분한다.** `store.json`: 본 파일·`.bak` 모두 **없으면** 빈 저장소로 시작, **존재하지만 둘 다 읽을 수 없으면(깨짐)** 앱이 오류 메시지를 보이고 시작하지 않는다(데이터를 덮어쓰지 않기 위해). `vault.json`: 둘 다 없으면 미초기화 상태. **둘 다 깨졌으면 미초기화로 취급하되, 새 보관함을 만들기 전에 깨진 파일을 `vault.json.corrupt-<YYYYMMDD-HHmmss>` 로 옮겨 보존**한다(사용자 데이터를 잃지 않게 하는 이 프로젝트의 선택, 결정 S1).
- 다른 OS 의 기본 데이터 폴더: 운영체제의 사용자 설정 폴더(`os.UserConfigDir` 에 해당) 아래 `TermGo/data`.

## 2. store.json 저장 규칙

- 최상위 객체 전체를 메모리에 두고, **변경 요청(최상위 키 단위 덮어쓰기)** 이 들어오면 즉시 메모리에 반영하고 **300ms 뒤 디스크에 저장**한다(연속 요청은 하나로 합침). 앱 종료와 백업 내보내기 직전에는 즉시 저장한다.
- 열 때 `groups`, `hosts`, `snippets`, `knownHosts` 가 없으면 빈 배열로 채우고 `version` 은 항상 1 로 둔다. **알 수 없는 최상위 키는 그대로 보존**한다.
- 읽기 요청에 줄 때 `settings` 는 저장된 값 위에 없는 키를 기본값으로 채워서 돌려준다(저장 데이터는 그대로).
- `groups`/`hosts`/`snippets` 키가 바뀌면 "동기화 예약" 알림을 낸다(§5).
- 접속하면 그 서버의 `lastUsedAt` 을 현재 시각으로 갱신한다(저장된 서버만, 즉석 접속은 제외).
- 호스트 키 기록: `knownHosts` 에서 `host:port` 로 찾고, 신뢰하면 `{hostPort, keyType, fingerprint, addedAt}` 로 추가/갱신.
- 설정 읽기 도우미: 불리언은 값이 없으면 기본값, 숫자도 같음.

## 3. 백업 파일

사용자가 저장 위치를 고르는 대화상자로 내보낸다.
- 기본 파일 이름 `termgo-backup-YYYY-MM-DD.tgbackup`, 기본 폴더는 문서 폴더, 필터 "백업 (*.tgbackup)". **가져오기**는 `*.tgbackup`, `*.btbackup`, `*.json` 을 모두 받는다.
- 내용(JSON, 들여쓰기 2칸, 권한 소유자 전용): 
  | 필드 | 값 |
  |---|---|
  | app | 새로 쓸 때 `termgo` (읽을 때는 `termgo` 와 `brightterm` 둘 다 인정, 그 외는 오류 "백업 파일이 아닙니다") |
  | version | 1 |
  | exportedAt | 밀리초 타임스탬프 |
  | store | store.json 최상위 객체 전체(설정은 병합 전 저장 값 그대로가 아니라 읽기 요청이 돌려주는 형태) |
  | vault | 볼트 파일 구조 전체 또는 없음 |
- 내보내기: 먼저 store 를 즉시 저장. 취소하면 `false`.
- 가져오기: 파일을 읽어 JSON 해석 실패나 `app` 불일치면 오류. store 는 **통째로 교체**하고 즉시 저장. 볼트가 있으면 볼트 가져오기 규칙(data/vault.md §6)에 따라 교체(잠김 상태). 성공하면 true, 취소하면 false.

## 4. 창 상태 (window.json)

필드: x, y, w, h, maximised, hasPos. 유효 조건: w ≥ 400, h ≥ 300. 동작은 behavior/lifecycle.md §4.

## 5. git 동기화

**목적**: 서버·폴더·스니펫·저장된 계정(볼트 항목)을 비공개 git 저장소로 여러 PC 에서 맞춘다. **설정·호스트 키는 동기화하지 않는다.**

### 5.1 저장소에 올라가는 파일 (`termgo-sync.json`, 저장소 루트 하나)
```
{ "format": "termgo-sync-1",
  "vault":   <볼트 헤더: data/vault.md §8>,
  "payload": { "iv": ..., "tag": ..., "ct": ... } }   // 보관함 키로 암호화, AAD = "termgo-sync"
```
payload 평문(JSON): `{ groups, hosts, snippets, creds }` — 각각 **id → 항목 JSON** 맵. `creds` 는 볼트 항목(암호화된 비밀 + 이름·종류·사용자 이름) 전체. 파일에는 항목 이름·서버 주소·계정 이름이 평문으로 나가지 않는다(볼트 헤더는 항목 없음).
쓸 때는 들여쓰기 1칸. 읽을 때 `format` 이 다르거나 JSON 이 깨지면 오류 "동기화 파일 형식을 알 수 없습니다".

### 5.2 기준 파일 (`sync-base.json`)
마지막으로 동기화에 성공한 시점의 병합 결과(같은 구조 `{groups, hosts, snippets, creds}`)를 로컬에 보관한다. 3방향 병합의 기준이다. 없으면 빈 데이터.

### 5.3 병합 규칙 (항목 id 단위, 컬렉션마다 동일)
항목 내용은 해석하지 않고 **JSON 동일성**(키 순서 무관)으로만 비교한다. 기준(base)·이 PC(local)·저장소(remote) 세 가지를 비교:
1. 기준에 **있던** 항목: 이 PC 나 저장소 중 **어느 한쪽이라도 지웠으면 삭제**(다른 쪽이 수정했어도 삭제가 이긴다). 둘 다 있으면: 이 PC 가 바꿨으면 이 PC 값, 아니고 저장소가 바꿨으면 저장소 값, 둘 다 안 바꿨으면 이 PC 값. (**양쪽이 모두 수정하면 지금 동기화하는 이 PC 가 이긴다**.)
2. 기준에 **없던** 항목: 이 PC 에 있으면 이 PC 값(양쪽에 같은 id 로 새로 생겼어도 이 PC 값), 없고 저장소에만 있으면 저장소 값.

### 5.4 한 번 동기화하는 절차
동시에 하나만 실행한다. 모드: 자동(기본) / "저장소의 보관함 받기" / "이 PC 보관함으로 덮어쓰기".

**새 PC 의 첫 연결 흐름**: 새 PC 도 앱을 쓰려면 먼저 로컬 볼트를 만들어 열어야 한다(잠금 화면의 최초 설정). 그 상태에서 저장소 주소를 넣고 동기화하면 저장소의 볼트가 이 PC 볼트와 달라 `vault-mismatch` 가 되고, 사용자가 "저장소의 보관함 받기"를 고르면 저장소 볼트의 마스터 비밀번호로 이 PC 볼트가 교체된다. 따라서 아래 사전 검사 3(볼트 잠김)은 그대로 유지한다(볼트가 아예 없는 상태에서는 동기화를 시작할 수 없다).

사전 검사(순서대로, 해당하면 그 상태로 종료):
1. 저장소 주소가 비어 있음 → 상태 `unconfigured`
2. 주소에 **계정:비밀번호@** 형태(`scheme://사용자:비밀번호@`)가 있음 → 오류 "저장소 주소에 비밀번호·토큰을 넣지 마세요 — 이 PC 의 git 자격 증명 도우미/SSH 키를 사용합니다"
3. 볼트가 잠겨 있음 → 상태 `locked`, 메시지 "보관함을 연 뒤에 동기화할 수 있습니다"
4. git 이 없음 → 상태 `nogit`, 메시지 "git 이 설치되어 있지 않습니다"

본 절차(**푸시가 거절되면 한 번 더 시도**, 총 2회):
1. 작업용 클론(`sync-repo/`)을 준비한다: 없으면 `git clone`, 있으면 원격 주소가 바뀌었을 때 갱신. `git fetch origin`. 원격에 `main` 이 있으면, 없고 `master` 가 있으면 그 브랜치로 체크아웃하고 원격 최신으로 하드 리셋. 둘 다 없으면(빈 저장소) 새 `main` 브랜치에서 시작. 실패하면 오류 상태.
2. 이 PC 데이터를 모은다. 저장소 파일을 읽는다(없으면 "원격 없음").
3. 원격 파일이 있고 모드가 "덮어쓰기"가 아니면:
   - **"저장소의 보관함 받기"**: 인증 요청 화면(종류 비밀번호, 세션 제목 "git 동기화", 안내 "저장소 보관함의 마스터 비밀번호", 저장 허용 안 함)을 띄워 비밀번호를 받는다. 취소·빈 값·틀림이면 상태 `vault-mismatch`, 메시지 "마스터 비밀번호가 맞지 않거나 취소되었습니다". 성공하면 원격 볼트 받기(data/vault.md §8)를 하고, 이 PC 의 기존 항목은 새 볼트로 대체되므로 이 PC 데이터는 빈 데이터로 보고, 기준도 빈 데이터로 하며, "변경됨"으로 표시.
   - payload 를 현재 볼트 키로 복호화한다. **실패하면 상태 `vault-mismatch`**, 메시지 "저장소의 보관함이 이 PC 의 보관함과 다릅니다"(사용자가 받기/덮어쓰기를 고른다). 해석 실패면 오류 "동기화 파일 해석 실패".
4. 병합: 원격이 있으면 (기준, 이 PC, 원격)을 병합, 없으면 이 PC 값 그대로.
5. 병합 결과가 이 PC 현재 데이터와 다르거나 "보관함 받기" 모드면 이 PC 에 반영한다: 볼트 항목 전체 교체, `groups`/`hosts`/`snippets` 를 병합 결과로 교체(**기존 배열의 순서를 최대한 유지**하고 새 항목은 id 오름차순으로 뒤에 붙임). 이 PC 가 바뀌었으면 "변경됨".
6. 원격이 없거나 병합 결과가 원격과 다르면 저장소 파일을 새로 쓰고 **그 파일만** 커밋해서 푸시한다. 커밋 작성자 `TermGo <termgo@localhost>`, 메시지 `TermGo sync`. 바뀐 게 없으면 커밋하지 않는다. 푸시 대상은 `HEAD:refs/heads/<브랜치>`. 푸시가 실패하면 1회 재시도, 그래도 실패하면 오류.
7. 기준 파일을 병합 결과로 저장하고 마지막 성공 시각을 **메모리에만** 기록한다(파일에 저장하지 않음). 결과 상태 `ok`(+ 마지막 동기화 시각, 변경됨 여부).

git 호출 규칙: 사용자 입력을 기다리는 프롬프트로 멈추지 않도록 터미널 프롬프트·askpass·자격 증명 도우미 상호작용을 끄고(`GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS` 비움, `GCM_INTERACTIVE=never`, 로케일 C), Windows 에서는 콘솔 창을 띄우지 않는다. git 오류 메시지는 끝 3줄을 ` / ` 로 이어 `git <명령>: <내용>` 으로 보여 준다. 앱은 git 자격 증명을 저장하지 않는다.

### 5.5 자동 실행 시점
- 볼트가 **열릴 때**(저장소 주소가 있고 "자동 동기화"가 켜져 있으면) 백그라운드로 한 번.
- 서버·폴더·스니펫·볼트 항목이 **바뀐 뒤 20초**(연속 변경은 마지막 변경 기준으로 합침). 동기화가 이 PC 데이터를 바꾸는 중에는 변경 알림을 무시한다.
- **10분마다**(볼트가 열려 있을 때만).
- 위 자동 실행은 저장소 주소가 있고 "자동 동기화"가 켜져 있을 때만. 설정 화면의 [지금 동기화]는 자동 설정과 무관하게 실행.
- 동기화가 이 PC 데이터를 바꿨으면 저장을 즉시 하고 "데이터 변경됨" 이벤트를 보낸다. 끝나면 항상 "동기화 상태" 이벤트(상태, 메시지, 마지막 동기화 시각, 변경됨)를 보낸다.
- "상태 조회": 저장소 설정 여부, git 설치 여부, 마지막 결과(마지막 동기화 시각은 **앱을 켠 뒤 성공한 시각**이며 성공한 적이 없으면 0 → 화면에는 "아직 동기화한 적 없음". 이 값은 파일에 저장하지 않는다).
