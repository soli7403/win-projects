# 12. 구현 공통 규칙

해당되는 항목만 적용한다. OS 중립(Windows 우선, 타 OS 동작 유지)을 전제로 한다.

## 설정·비밀값
- 설정은 toml + env. **모르는 키는 거부**해 오타를 기동 때 잡는다. `deploy/config/*.example` 이 곧 스키마.
- 비밀값은 코드·git·로그에 넣지 않는다. 키가 든 URL 도 로그·오류 문구에 넣지 않는다. OS 보관소(Windows DPAPI/자격 증명 관리자 등)나 권한 제한 파일을 쓴다.
- 호스트마다 다른 구성은 코드에 박지 않고 설정에 둔다.

## 데이터·상태
- 마이그레이션은 **추가만** 한다. SQLite 는 CGO 없는 `modernc` 를 쓴다.
- 상태 전환은 조건부 UPDATE(`from → to`). 잡은 멱등으로 만든다.
- 원본 페이로드(JSON)는 보관한다.
- 시각은 저장 시 UTC, API 는 RFC3339, 날짜 경계만 현지 시간.
- sqlc 사용 시 쿼리 파일은 ASCII 전용, `BETWEEN sqlc.arg()` 대신 `>=`·`<=`.

## 외부 호출·계약
- 외부 호출은 인터페이스 뒤에 두고 테스트는 Fake. 실제 통합 시험은 `-tags integration`.
- **되돌릴 수 없는 요청**은 전송 실패 시 재시도하지 않는다 (`unknown` 으로 두고 조회로 맞춤).
- 계약 변경은 설계 문서·픽스처·서버·클라이언트를 같은 변경에서 고친다. 기존 필드 의미는 바꾸지 않는다.
- 판정·규칙은 순수 함수로 분리해 단위 테스트한다.
- Go 는 다른 모듈의 `internal` 을 import 할 수 없다. 재사용 시 복사하고 출처를 주석으로 남긴다.

## 웹/프런트 UI
- 외부 문자열은 남이 쓴 글이다: `innerHTML`·인라인 스크립트 금지, CSP 적용.

## 빌드·배포
- `Makefile` 대신 Windows 에서도 쓰려면 `go build`/`wails build` 명령을 `docs` 에 명시하거나 스크립트(`.sh` + `.ps1`)를 쌍으로 둔다.
- 설치 스크립트는 멱등 + `--dry-run`, 설정 검사(`-check-config`) 실패 시 아무것도 바꾸지 않는다, 바뀌었을 때만 재시작.

## 제외 (원본의 macOS/iOS 전용 항목)
launchd·codesign·외장 볼륨·iOS/APNs 규칙은 해당 플랫폼 프로젝트를 만들 때 별도 문서로 추가한다.
